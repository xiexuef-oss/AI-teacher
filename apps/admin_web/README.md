# admin_web：内容审核后台

docs/03 的 P11 `/admin/review`，PRD P0 第 9 条"管理后台最小审核流"。审校员在这里审题目、答案和解法：
`draft → reviewed → published`，发现问题可以撤回（`withdrawn`，终态）。设计取舍见 `docs/ADR-008_内容审核最小流.md`。

Vue 3 + Vite + TypeScript，路由用哈希模式，公式用 KaTeX。**接口类型不手写**：`src/api/schema.d.ts` 由
`contracts/openapi.yaml` 生成，契约改了而没有重新生成时 `npm run check:api` 会失败。

## 运行

需要 Node 22（开发机是 22.18）。先在仓库根目录启动 API（它会显式开启本地身份 Mock，并带 3 道待审样题）：

```
uv run python tools/run_dev_api.py
```

再启动后台：

```
cd apps/admin_web
npm install
npm run dev          # http://127.0.0.1:5174
```

登录页只有"本地开发登录"：每点一次，就在本机创建一个新的审核员（或管理员）身份。真实登录方式还没有定（Q-03），
所以这个后台目前只能在本机开发环境里进入，后端没有开启本地身份 Mock 时登录页会说明原因。
后端地址默认 `http://127.0.0.1:8000/api/v1`，用环境变量 `VITE_API_BASE` 覆盖。

演示流程：用审核员身份进入 → "待审"页签里有 3 道样题 → 打开一道 → 二审通过 → 上线；回到队列，
"已上线"的数字加一，学生端的练习列表里也有了这道题。再去"下线"它，必须写原因。

修改：打开一道待审（或已下线）的题，点"编辑题目"，改完"保存为新版本"——旧版本留着，新版本回到待审，你成为它的提交者，
所以要换另一个身份（退出后以管理员进入）才能二审。已上线的题要先下线才能改。

解答题：审核页里能看到小问、按小问列出的参考答案、按小问分组的自查要点；编辑器里小问与参考答案是同一批行，
自查要点是另一批行（"所属小问"用下拉选，"整份解答"针对全部作答）。自查要点是一张清单，不带分值，不是评分标准（ADR-011）。

实验题：审核页里多了"实验安全提示（风险等级）"、数据表（留空的格子标出来）和每个留空格子的参考值；编辑器里能改安全提示，
数据表和"留空格子的参考值"是两段 JSON（键是"表键.行键.列键"），要点的"所属"除了小问还能选数据表。每道实验题必须有安全提示，
`high` 级别的实验现在不收录，程序校验会指出来、通不过审核（ADR-013）。

证明题：审核页里能看到已知（编号 ①②③）、求证、参考证明（每步的阶段、文字、依据，表格）和按证明阶段（前提、构造、推理、结论，整份证明在最后）分组的自查要点；编辑器里已知是一组文本框、求证是一个文本框，参考证明是一组行（阶段下拉、文字、依据，可以上移、下移、删除），要点的"所属"下拉是四个阶段加"整份证明"。参考证明要示范每一步有依据、以结论收尾，程序校验会指出来（ADR-015）。

对比：保存之后点"查看这次改了什么"，或者在题目页的"版本与审核历史"里点"对比最近两个版本"、点某个版本徽章回看那一版的完整内容。
对比页左右并排，删掉的片段红底划线、新加的绿底；默认只显示有改动的部分，勾选"显示没有改动的部分"看全部。

## 已知限制

- 版本对比只能两两对比，不能导出；文本对比是字/词级的，挪动整段会显示成删一段、加一段（ADR-010）。
- 编辑：附件原样带过去、不能改；图解模板与参数、判定规则要手写 JSON；选择题和填空题的评分细则也是手写 JSON；每次保存都是一个新版本。
- 解答题的小问、参考答案、自查要点可以改；小问的键被改名后，指向它的要点要手动改（程序校验会指出来）。
- 证明题的参考证明里，阶段是下拉，文字和依据是纯文本框（公式写在 `$…$` 里，下面没有公式预览）；改了阶段之后，指向该阶段的要点不会自动改，程序校验会指出来。
- 实验题的数据表是 JSON 文本，不是表格式编辑器；改了表的结构后，"留空格子的参考值"里对应的键要手动改（程序校验会指出来，不会自动改写）。
- 地区适用标记只能查看，不能在这里审核。
- 队列分页是 offset 游标，题量大了要改成数据库侧的键集分页。
- 只在 Chrome 里看过；无障碍只做了语义标签和键盘可达，没有用读屏软件走过。
- 安装时 npm 会对 `nopt`、`abbrev` 报"要求 Node ≥ 22.22"的警告：它们是 `@vue/test-utils → js-beautify` 的命令行解析依赖，
  测试和构建不会用到，开发机 Node 22.18 上一切正常。jsdom 固定在 29（31 要求 Node ≥ 22.22）。

## 结构化题目导入（CONTENT-IMPORT-001）

审核队列点击“导入题目”，下载示例、填好题目及来源与使用依据，再选择 JSON 文件或粘贴内容。
确认后只保存为待审草稿，打开草稿即可检查问题、编辑并交给另一位审校员二审。失败重试复用幂等键。
来源声明须人工核验；示例未经学科审校。暂不支持 PDF、Word、图片、批量导入或 AI 变式。


批量审核（ADMIN-301）：在队列选择最多50题，进入逐题确认页。每题独立选择决策、核对版本/答案/解法并明确勾选；二审与发布必须分别确认，不会自动发布。普通业务校验失败仅回滚该题，成功结果与批次幂等回执在一个有界事务中提交；意外进程、连接或事务故障则整批未提交，可复用原键重试。已返回的失败子集在刷新并重新确认后使用新批次键，成功项不会自动再审。原请求和结果按账号保留在当前标签页sessionStorage最多30分钟，退出账号清理本用户数据。


本地审核附件（MEDIA-301）：默认关闭，显式设置TUTOR_MEDIA_LOCAL_ENABLED=true才启用；根目录及大小/像素/临时有效期由服务端media_*配置控制，配置不是生产留存政策。图片先暂存并校验MIME、大小和SHA-256，再确认数据库元数据；只有已确认且未过期/未删除附件可预览。上传者可直读，独立审校员仅能预览当前题目真实引用的附件；不能通过向题面填入别人UUID取得权限。新增引用限本人附件，原题已存在引用可保留。裸媒体接口仍禁止学生读取；学生读取仅限下述SUBJECT-301受控题目引用，未接外部S3/OCR/手写备份。前端只暂存恢复请求元数据与幂等键，不持久缓存原图Base64。逻辑删除同事务提交，物理删除在提交后重试清理；重启执行过期/孤儿清理。确认/幂等回执失败可能留下不可读临时孤儿，按配置清理，绝不据磁盘ready状态擅自恢复DB可见性。


题面静态图片（SUBJECT-301）：PNG/WebP动画及所有多帧输入被拒绝，不截取首帧伪报成功，读取旧媒体也复验。审校员需在当前版本逐图授权预览、等待图片加载并明确勾选声明；这仅记录审校声明，程序不证明人实际完整看图。声明绑定qid/version/media/sha/actor/expiry，与幂等回执同事务。二审和发布各自校验本人声明，发布还要求独立reviewed_by的记录有效；不能靠发布者自己的声明代替原二审记录。任一版本/摘要变化、删除或过期均失效，批量审核不代替逐图声明。学生接口仅student角色并按已发布题目当前引用授权，家长403，草稿/未引用/旧记录/过期删除不可读；裸媒体接口仍禁止学生跨owner使用。Flutter仅展示kind=image的受控字节，不加载任意URL/脚本，不持久缓存；16MiB字节/20MP源像素/单帧/1024px目标解码受限，替代文本及重试独立于作答和本机草稿。附件只属于题面，不能将答案或解析图放入此入口。默认仍是本地临时媒体原型，不确定任何生产留存政策。
