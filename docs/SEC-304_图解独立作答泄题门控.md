# SEC-304：独立作答阶段的图解泄题门控

状态：设计与先红回归准备；核心改动等待当前全量变异终态及主线程分配。2026-11-16。

现有注册表和事件Schema保证模板、有限数值和范围合法，不保证教学内容适合独立作答阶段。
本任务不以答案词表或数值黑名单宣称计算安全，不新增几何或工艺模板。

| 风险面 | 已观察到的实现与具体证据 | 必须守住的边界 |
|---|---|---|
| 化学计算输出 | chemical_flow用10/100×1/1×44绘制4.4g，恰为chem-conservation-co2答案；语义描述也计算同值 | 提交或明确查看完整解析前，不下发规格，客户端没有题目绑定参数可据此绘制 |
| 物理计算输出 | force_diagram的30°、g=10、mu=0生成5m/s²；motion_chart会显示位移积分结果 | 注册模板不代表计算结果是无答案提示 |
| 最值与区间 | rectangle_area显示最大面积/取等信息；quadratic_graph显示当前函数递增区间与顶点；数轴可直接呈现答案区间 | 默认都按可能包含解析处理，不能因template_id合法而独立阶段放行 |
| caption与fallback | normalized_visual允许题目caption和seed static_fallback覆盖；内容校验未将其当独立阶段泄题面检查 | 门控必须位于整个visual payload之前，不只隐藏画布或caption |
| 元数据与默认参数 | seed/旧DB教学对象可夹带independent_safe、requires_solution等未授权额外元数据，缺失参数由注册表补默认；真实数学结果可在范围内产生 | 元数据不得授权绕过会话状态；不把省略参数、来源“工程样题”或审核标志当安全证明 |
| 模型与规则分支 | Gateway检查字符串与数值范围；规则编排直接发审核visual，不经过模型；数值运算和Dart describeVisual文本发生在客户端 | 不能依赖Gateway的字符串检测覆盖规则内容或派生数值 |

## 最小兼容实现

- 保持TutorStep、notice和visual事件形状，保留现有模板与范围，不增加“安全”字段。
- _request_visual继续优先执行复测限制并校验模板；无图解仍返回visual_not_available。
- 有图解且未提交、used_solution=False时只返回无答案notice，既不返回template_id/params/caption/static_fallback，也不标记已看解析或已获辅助。
- 即使visual动作携带confirm_end_independent=True也不能绕过。完整解析必须通过现有request_standard/fast动作，使用既有明确确认和used_solution审计。
- 已提交或已明确查看完整解析后保留图解。既有已提交判定与正确率不重算。
- 将“看图理解”的建议文案改成解析阶段语义；Flutter现有notice与完整解析确认流程可继续使用，不需要改草稿或solve_controller。

## 回归证据

新文件tests/api/test_visual_security.py：4.4g、5m/s²、最值、区间各自独立阶段无规格；visual自带确认无效；caption/fallback及seed安全标记无效；提交后可用且评估不改；明确完整解析后可用；复测禁用优先。
新增测试先出现8失败/9通过，门控落地后与既有辅导流程共71通过；SEC304绕过门控变异1/1被捕获。导出100份真实契约响应样例，Flutter fake同步独立阶段notice。浏览器流程已加入独立阶段无规格、明确完整解析动作记录及解析后图解三项检查，待PROD302 A与草稿整合后统一执行，尚不声称浏览器已覆盖此门控。orchestrator.py已交还PROD302 A。

SUBJECT-302/303只读结论：chemical_flow是计量换算，并非工业工艺；几何模板缺失。后续新增图示仅呈现题面给定关系，不加入可推导当前答案的操作、辅助线、角度或结果展示。先完成SEC-304与整合门禁再实施。

## 保护边界

本轮保护题目绑定的教学事件：真实作答流程在提交或完整解析记录之前，不下发当前题目的图解参数、说明和后备文本。Flutter独立的通用模板演示页不绑定题目/会话，本轮保留；不把客户端深链接或通用计算工具当作防作弊安全边界。题面静态附件继续使用SUBJECT-301发布引用与独立审校声明门控，不与解析图解混用。
