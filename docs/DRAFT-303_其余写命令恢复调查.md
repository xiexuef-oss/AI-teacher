# DRAFT-303 其余写命令恢复调查

状态：调查基线与分阶段实施清单。303A提交/自查/同步已完成固定产物工程验收；303B辅导/复测实现后正在真实浏览器整合验收，专篇分别记录。下表“现有实现”保留调查时基线，不代表最新源码。后续设置资料、家长、扫描和审核后台写入恢复仍待实施；创建与学习动作完成不能代替全部入口。

## 已见调用与需验证的失效路径

| 动作 | 现有实现 | 本包需验证/补齐 |
|---|---|---|
| 提交 | SolveController使用内存PendingKeys；每次调用重新生成elapsedMs/body | 同键重试时elapsedMs变化可能触发指纹409；请求成功丢响应后重启须恢复原提交，不能重评、重排复测或丢稿 |
| 草稿同步 | key含attempt、baseRevision及JSON String.hashCode | hashCode不是明确持久协议；响应丢失后必须保留原请求体/键，再协调期间新增笔迹，不能将同一命令重构成新内容 |
| 辅导 | 内存PendingKeys按action/confirmed区分 | 丢响应重启重试不得重复增加事件、消耗提示层级/预算；成功后同类新动作须是新intent，不能按内容永久去重 |
| 复测完成 | 内存PendingKeys | 不重复推进stage；先恢复服务器既有提交和完成结果，不能把业务409当成功，也不能另开会话绕过 |
| 主观题自查 | key由attempt和marks JSON hashCode推导 | A保存→B保存→再改回A，不能重放首次A回执却让服务端仍保留B；同次未确认动作应冻结body，已确认后新动作须新intent |
| 家长邀请码生成/兑换/撤销 | 页面内存PendingKeys，兑换动作名含本机输入但header标签已脱敏 | 重启/退出恢复同一次动作；不能无限自动生成作废旧邀请码，不能把明文邀请码无条件写通用journal |
| 扫描上传/确认 | ScanDraft.toJson持久化keys，页面各阶段先save再发请求 | 已有跨重启key保存，不能误标纯内存；完整body没有作为intent冻结，原图只在内存，原图缺失应明确重新选图/校验原指纹，不假称可自动重放二进制 |
| Profile更新 | core/data.dart ProfileController.save直接updateProfile，成功后写本机缓存 | 当前未传幂等键，也未先保存pending body；需契约/客户端与本机先落盘一起设计，不能只改通用header生成 |
| 本地身份Mock | AuthController调用公开createLocalIdentity，成功后才保存token/userId/role；重新登录先清槽 | 丢响应可能遗留未知身份，仅原型边界，不等于真实账户恢复；与AUTH-301/Q-03分别记录，不能擅自引入生产身份方案 |
| 设置、导入、审核等其余客户端写入 | 按模块继续盘点 | 列出已持久化/仅内存/自然幂等/明确Mock例外，补齐缺口，不假定上述学习命令覆盖全部客户端 |

表中失效路径除已有实现事实外尚需实际红测，不能仅凭静态阅读声称已复现或已修复。

外部入口只读补查：扫描在scan_page各写请求前创建key并await草稿保存，ScanDraftStore串行写入keys；确认body仍现场由题干/expressions构造，上传原图不进该草稿。后台通用client只透传key/body，题目编辑/审核、批量审核、文档导入和媒体组件各自有内存pending/fingerprint；需进一步核对每个组件的持久恢复，不能仅凭Map变量就断言没有持久化。轻量调查首轮对scan持久性判断不充分，已按完整toJson/load/save源码更正；未执行本包失效红测。

## 恢复协议要求

动作发出前持久保存intent、用户/资源/版本、method/path、固定幂等键和生成类型序列化的完整body。网络失败或响应丢失重放同一快照；新编辑另存本机，不能偷偷变更pending body。结果先落盘再ack；未知状态与损坏记录fail closed，保留输入和原始记录。

使用代际、scope lease及302新增active选择CAS，迟到结果可以记引用但不能替换另一页面选择。不能把“payload相同”视为“同一个动作”；必须区分未确认重试与成功后的另一次主动操作。跨账号不重放，404/409按资源状态恢复，不盲目换键。

提交elapsedMs等不再每次重试重算；辅导confirmEndIndependent等确认位必须封入原动作，不能自动从未确认变确认。副作用已有服务端回执才应用，恢复时读取最新attempt/session/events，不用过期回执复位已使用提示或完整解析的标志。

敏感能力码不能默认进入通用明文journal。邀请码兑换可仅保留非可兑换指纹/intent并要求学生或家长再次输入原码才能继续，或在明确评估过的受保护本机存储中保存；不得在header标签、日志、测试证据中暴露原码。真实身份与监护核验仍等待Q-03，不借本包自行冻结认证方式。

## 建议顺序与证据

1. 学习动作红测：提交失败后elapsed变化；提交实际成功丢响应后重启；同步期间继续输入；辅导真实成功丢响应后事件/层级不重复；复测不重复stage；自查A→B→A服务端最终确为A。
2. 共用命令存储/执行器在确认各动作语义后实现，禁止做不分动作的自动离线重放队列。测试每个持久窗口失败、晚到结果、资源已提交/完成、撤销权限与跨账号。
3. 家长相关动作先补敏感数据与撤销即时生效回归，再接安全恢复界面，不扩大父母可见数据。
4. 盘点其余学生/审核后台写入口，逐项记录固定键/body、恢复方式与当前缺口；Mock身份引导单列边界，不声称生产登录完成。
5. 契约如变更必须先改契约、再红测实现、生成Dart/后台类型/真实样例；实际浏览器丢响应和刷新验证，关键规则变异，完整门禁，具备设备后的原生重启另验收。
