# SEC-302 解析隔离与验证

状态：两种显式运行模式已实现；生产部署仍需按目标系统验证，不能把任一工具当作通用安全保证。

## Windows process 模式

现有独立解析进程使用Job Object清理子进程树，可配置任务/进程提交内存与累计用户态CPU上限。
本地启动脚本在Windows默认512MiB、20秒CPU；另有墙钟超时、原文件/解压/页数/像素/输出上限。
已实测内存超额、CPU配额、超时子进程清理和正常自编DOC转换。
该模式没有操作系统级网络隔离，不应对公网开放不可信转换器。

## Linux linux_bwrap 模式

必须显式提供隔离工具、独立Python运行时以及硬资源配额；缺失或启动失败不回退。

```
TUTOR_IMPORT_ISOLATION_MODE=linux_bwrap
TUTOR_IMPORT_LINUX_BWRAP=/opt/tools/bwrap
TUTOR_IMPORT_LINUX_RUNTIME=/opt/tutor-parser-venv
TUTOR_IMPORT_MEMORY_LIMIT_BYTES=2147483648
TUTOR_IMPORT_CPU_LIMIT_SECONDS=20
```

路径为部署者提供的Linux路径，不是客户端输入。运行时应由锁定依赖与哈希校验构建。
命令只读挂载/usr、共享库、独立运行时和tutor_api代码包，不挂载宿主/home、/mnt或完整根目录；
使用独立user/PID/network/IPC/UTS namespace，丢弃capabilities、清空环境、独立会话、限制/tmp大小。
prlimit限制地址空间及每进程CPU时间；这与Windows提交内存/任务累计CPU口径不同，不能直接比较数值。
可显式设置 `TUTOR_IMPORT_LINUX_CGROUP=true`，通过用户systemd scope限制整棵进程树的内存、禁用swap、限制进程数和CPU带宽。
该模式要求可用的用户systemd管理器与cgroup控制器，启动失败不回退；`TUTOR_IMPORT_LINUX_TASK_LIMIT`默认16，`TUTOR_IMPORT_LINUX_CPU_PERCENT`默认100。
CPU带宽与累计CPU时间不同，墙钟超时仍保留。当前没有seccomp调用白名单，不能声称已抵御全部内核或解析器漏洞。

DOCX、文字/扫描PDF、PNG/JPEG和JSON使用相同解析入口。2026-11-17已补本机Ubuntu的DOC转换运行时及实际验证，见下文；不把Windows转换成功算作Linux证据，也不自动启用生产转换。
生产环境未启用真实外部模型；识别经网关的授权和留存前置条件保持不变。

## 已执行验证

Ubuntu WSL2中以非root运行bubblewrap，独立运行时从锁定哈希的轮包离线安装。
`tests/integration/test_linux_parser_sandbox.py` 当前显式配置下11项通过（包含下述新增DOC及网络正向对照）：

- 自编PDF和DOCX正常提取。
- 隔离外真实存在的测试文件在隔离内不可见；环境秘密不传入；先证明宿主临时TCP监听可达，再验证隔离内无法连接。不依赖某个Redis端口恰好未启动。
- 超时后子进程未继续输出。
- 通过Settings选择隔离并应用配额可正常解析；指定不存在的工具时明确失败。
- cgroup限制进程树继续派生子进程；实际读取内核memory.max、memory.swap.max、pids.max和cpu.max与请求配额一致。

测试配置路径用 `TUTOR_LINUX_SANDBOX_CONFIG`，只保存运行时路径和测试sentinel，不包含真实凭据。
未配置时集成测试明确skip，不能算通过。

## Linux DOC 运行时补齐（2026-11-17）

本机Ubuntu WSL2已安装官方仓库的无GUI Writer依赖，实际版本
`LibreOffice 24.2.7.2 420(Build:2)`；安装增加61个包，未升级或移除其他包。
版本、发行包及原生启动器SHA-256见 `var/sec302-linux-doc-runtime.json`。
测试显式使用 `/usr/lib/libreoffice/program/oosplash`，它是此次发行包的原生启动器；
单独运行`soffice.bin`在初始化转换时会退出，不能把版本查询成功当作可转换证明。

Ubuntu安装包的`/usr/lib/libreoffice/share/registry`链接到`/etc/libreoffice/registry`。
原隔离环境缺少这个路径，真实二进制DOC转换失败。修复只有两处接线：
仅当格式为DOC且显式配置转换器时，为既有sandbox增加`/etc/libreoffice`的只读挂载。
其他格式或未配置转换器时不增加挂载；不暴露宿主整个`/etc`、`/home`、`/mnt`或网络。
不额外挂载字体配置；当前只承诺文字片段提取，版式、公式和媒体仍保留原有人工核对警告。

后端本身运行在Linux时可显式配置：

```text
TUTOR_IMPORT_ISOLATION_MODE=linux_bwrap
TUTOR_IMPORT_DOC_CONVERTER=/usr/lib/libreoffice/program/oosplash
```

仍须提供前述bwrap、独立Python运行时和资源配额；默认转换器仍为None。
此路径是本机Ubuntu安装布局，不作为其他发行版或生产镜像的已验收配置。
Windows集成测试配置可额外提供`doc_converter`字段；不提供时新增真实DOC测试明确skip。

验证只使用固定自编RTF在宿主生成具有OLE签名的真实Word 97 DOC，再调用实际
`parse_isolated(..., 'doc', settings)`在沙箱中转为DOCX并提取，已核对中文、英文文字；
普通bwrap和cgroup模式均通过，缺失转换器仍明确失败。宿主生成步骤只处理固定自编材料，
并非允许不可信上传绕过隔离。另实际读取DOC模式的`/proc/self/mountinfo`核对注册表为只读。

证据：

- `var/sec302-linux-doc-red-r3.log`：运行时补齐前两种DOC模式均因隔离内转换失败；
  更早的编码/启动器准备问题仅作诊断，不计作行为红测。
- `var/sec302-linux-doc-all-imports.log`：文档单元、导入API、运行器及真实Linux验证共192项通过，零跳过；其中11项是真实Linux/WSL集成。
- `var/sec302-linux-doc-mutations/mutation-evidence-3c34w3_n/summary.json`：3/3捕获，覆盖DOC接线、私有网络及注册表只读挂载；无基线失败、跳过或执行错误。
- `var/sec302-linux-doc-source-verification.json`：独立快照368文件恢复一致，原生WSL也从该快照加载代码，关键源与主工作区一致。
