## 行为

新SDK在发送之前，将SDK专用游标与原dispatch_unknown及预占一起提交：候选序号、重试序号、供应商/路由HMAC摘要和external分类。路由摘要绑定候选顺序、解析后的模型以及external分类，不保存密钥或提示词。失败结算时，再原子保存已确认的retry/fallback动作。

同一学生伪名、同一request_id及相同请求/提示指纹再次调用时，只有全部已有尝试均已结算、最后一笔确认允许继续、且游标与当前路由/模型身份一致，才能从下一次尝试继续。实际权限、价格、当前重试次数、请求/每日额度及共享暂停仍重新检查。既往外部供应商历史由持久游标恢复，不能通过重启绕过跨供应商隐私策略。

同供应商续试必须推进重试序号；回退必须向后选择候选，不能倒退或重复原游标。原fence和预算交易继续保证多个恢复进程只有一个实际发送。响应provider_calls仍表示本次执行的新尝试数，历史尝试以账本/审计为准；请求槽不重复收费，原日及前次估算/超额成本保持。

路由/解析模型或供应商身份摘要变化时返回INVOCATION_CONFLICT，不猜测新游标；未结算或可能已发送的调用返回INVOCATION_UNCERTAIN。COST-310/311旧记录缺少游标时不自动补造或续跑。成功结果已经结算的请求仍返回INVOCATION_ALREADY_SETTLED，不重复调用、不伪造恢复正文。

这只解决“确认失败已结算之后退出”的续跑。未知调用重发、已成功模型正文/业务交付恢复、旧SDK入口与API业务编排迁移、生产存储和Q-07留存/地域/条款仍未完成；外调默认禁用。
