# ADR-009 题目编辑与新版本

状态：已采纳（2026-11-12）。范围：docs/07 §4"修改题干或答案后增加版本，旧版本留痕"，接在 ADR-008（最小审核流）之后。
后端 `POST /admin/questions/{id}/versions`，界面在审核后台的题目页里。

## 决策

**1. 整体替换，产生新版本。** 请求是可编辑内容的完整替换（标题、难度、年级、题面、答案、教学辅助、解法、知识点、评分细则），不是补丁：
没打算改的部分原样传回，界面上不会出现"没传的字段是清空还是保持"的歧义。保存产生 `version + 1`，旧版本的题面、答案、教学辅助、
解法、评分细则的行原样留在库里（新行，不改旧行）。题型、学科、答题方式、来源、地区标记不在这里改（改了等于另一道题或另一种授权）。
题面里的小问与附件（本切片没有这样的题）原样带过去，不会被编辑悄悄丢掉。

**2. 哪些状态能改。** `draft`、`reviewed`、`withdrawn` 可以改，**已上线的要先下线**（409 `invalid_transition`）。
这样上线的内容不会被悄悄改掉，也不需要"线上是第 1 版、待审的是第 2 版"这种两个版本并存的状态——那要把 `published_version`
和 `version` 拆开，学生端所有读题的地方都得跟着改，不在这次范围里。代价是改一个错别字也要先把题下线；下线的题学生立刻看不到，
新版本二审、上线之后回来。

**3. 新版本回到 draft，改的人成为提交者。** 审校人与解法确认全部清空（新版本的解法行一律 `reviewed=False`），
必须由另一位审校员重新二审。`Question.created_by` 表示"当前版本的提交者"，改的人写进去——否则审校员 A 改了内容再自己二审，
就绕过了"提交者不能审自己的题"。历史上谁提交过哪个版本，看 `question_versions.created_by`。

**4. 保存不做程序校验。** 草稿可以是半成品，不然只能一次写对才能存。校验结果在保存后的详情里（`check_problems`），
`approve`、`publish` 之前必须清零（ADR-008 决策 3）。只拦保存了就没法存的东西：知识点不存在或不属于这道题的学科（422），
同一种解法重复（422），请求里有不认识的字段或超长的文本（422，上限写在契约里），版本落后（409）。

**5. 没有改动不产生空版本。** 422 `no_changes`。比较用的是和详情接口同一种表示：把详情原样传回，必须被认作"没有改动"——
测试对全部 20 道样题都做了这个来回（`test_a_round_trip_of_every_seeded_question_is_recognised_as_no_change`），
前端对选择题和带规则、单位、图解、快速解法的填空题也做了来回测试。审计和历史里记录改动了哪几部分（`changes`）。

**6. 泄题标记跟着答案走。** 题目运行时用一份"不能出现在提示和模型输出里的写法"（`teaching.leak_markers`），
由两部分合成：审校员补充的（答案的写法太多、程序列不全，比如表达式答案），和由答案自动推出的。改了答案，自动那部分必须重算，
否则旧答案的标记留着、新答案漏过去。详情接口只给出"审校员补充的"那部分（库里存的完整标记减去自动推出的），
保存时再合成；测试确认了两件事：改答案后标记换了，审校员补的标记来回之后还在。

**7. 学生已经开始的会话不受影响。** 会话开始时记下题目版本，之后的判分、提示、解析、图解都按这个版本取
（`session.question_version`）。测试走了完整的一遍：学生开了第 1 版 → 题被下线、改成第 2 版（答案换了）、二审、上线 →
旧会话提交旧答案仍判对，新开的会话按第 2 版判分。

**8. 顺带修了上一个提交留下的问题：下线的题还留在学生的复测列表里。** 学生答错后会安排复测；题被下线（或者改成待审的新版本）后，
复测项还在、时间不变，列表里照样显示，但学生开不了会话（题不是 published）。现在复测列表只列 published 的题，
题目重新上线后复测项自然回来。是写"下线后改题再上线"的测试时发现的。

**9. 输入比输出严格。** 请求里不认识的字段、超长的文本、过多的条目一律 422；响应用的模型保持宽松，库里的旧数据多出字段不会让读取失败。
契约里给 `QuestionContent`、`AdminTeaching`、解法输入补了长度与条数上限。

**10. 审核后台的编辑器。** 表单与请求之间的转换（`src/editing.ts`）是纯函数，来回测试保证"没改就是没改"。
判定规则、单位规则、图解参数、评分细则用 JSON 文本框（结构复杂，先不做可视化编辑），解析不了就逐条说明原因而不是悄悄丢掉；
提示、步骤、要点、条件、标记用"一项一个文本框"的列表；题干和选项有 KaTeX 实时预览；"保存为新版本"在没有改动或者有输入错误时不可用；
网络失败后重试同一份内容复用幂等键，内容变了就换新键（和决策面板一致）。

## 没做、没验证的

- **看不到旧版本的内容。** 旧版本留在库里，详情接口只给当前版本，审核后台只列出版本号和时间，没有"对比第 1 版和第 2 版"。
  要补一个按版本取内容的接口和对比界面，"旧版本留痕"才算对审校员可用。
- 知识点关联不分版本（按题目整体替换，不影响已有会话）；地区适用标记、来源信息不能在这里改。
- 小问、附件还没有编辑界面（原样带过去）；图解模板的名字和参数范围要手写，没有从模板注册表里选；评分细则只能写 JSON。
- 没有"保存草稿但不产生新版本"：每次保存都是一个新版本，改动很多次会有很多个版本。
- 浏览器里用真实后端走过：审核员改一道待审题 → 保存为第 2 版 → 改的人自己二审被拦住并说明原因 → 另一个身份二审、上线 →
  学生端取到第 2 版；上线之后"编辑题目"不可用。没有走过：下线后改题再上线、编辑过程中版本冲突（只在组件测试里验证）。
- 测试：后端 `tests/api/test_admin_versions.py` 25 项；后台 `editing.test.ts`、`editor.test.ts` 共 21 项；变异检查新增 5 条
  （已上线也能改、解法审核标记没清、改的人能二审自己的修改、没有改动也产生版本、复测列表列出已下线的题）。
