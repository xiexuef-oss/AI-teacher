状态：已采纳（2026-11-11）。范围：ADR-006 认领的切片：后端、模型网关、契约、迁移，以及 Flutter 学生端和 Dart 契约包。前半部分是后端，Flutter 学生端的决策在"Flutter 学生端"一节。

## 决策

**1. 契约文件是唯一的接口描述。** `contracts/openapi.yaml` 由人维护；FastAPI 自动生成的文档已关闭，避免出现第二份。测试客户端把每个真实响应按契约校验：状态码必须在该操作下声明过，响应体必须过 schema（对象一律 `additionalProperties: false`，服务端多发一个字段也会失败）。

**2. 教学事件分两层描述。** OpenAPI 里只有事件信封，payload 的结构在 `contracts/tutor_event.schema.json`。两处的枚举和必填字段由测试对照。服务端每写入一个事件都先过 Schema，不论它来自审核内容、规则还是模型。

**3. 开发态只支持 SQLite。** 表由 ORM 直接创建；`make_engine` 遇到非 SQLite 的地址会直接报错。原因是本地身份 Mock 和幂等记录（`proto_` 表）只是原型期的替身，在换成真实登录和 Redis 之前不应该连到 MySQL 上。ORM 与 `migrations/*.sql` 的表、列、类型由 `tests/migrations` 逐列对照，`proto_` 表被排除在外。

**4. 迁移用 SQL 文件，没有引入 Alembic。** docs/04 以 `001_init.sql` 为准，本阶段没有需要 Alembic 的场景。`tools/verify_migrations.py` 默认做静态解析和 ORM 对照；带 `--mysql-url` 时在空库上执行全部迁移并反射核对——这个模式写好了但没有运行过，开发机上没有 MySQL。

**5. 幂等记录与业务写入同事务提交。** 同键同请求重放首次响应，同键不同请求 409，失败的请求不留记录。提交接口另外把"按用户加盐的键摘要"写进 `attempts.request_id`（唯一约束）。

**6. 先提交，再返回响应。** 数据库提交在构造响应之前显式完成，不放在 FastAPI 依赖项的收尾代码里（收尾可能在响应发出之后才执行，提交失败客户端就看不到了）。

**7. 模型网关是同步实现，调用模型前先结束数据库事务。** 网关的审计和用量用自己的短事务写库。编排器在调用网关之前保证没有任何未提交的写入，并结束读事务；模型返回后重新读取会话再落事件。这样模型调用期间不占数据库，SQLite 上两个连接也不会互相等锁。流式输出与取消留到真实模型接入时再做。

**8. 内容来源的优先级：审核内容 → 模型网关 → 规则降级。** 分层提示、常规与快速解法、图解都直接引用审核内容。本阶段只有"换种讲法"在题目没有审核文案时才走网关（样题里有一半左右特意不带，用来走通这条路）。网关不可用或输出被拒时下发 `fallback` 事件，不编造内容。

**9. 判题不用 SymPy，用自写的受限解析器加数值取样。** docs/02 说"可用 SymPy 辅助验证"。没有采用的原因：学生输入不可信，`sympify` / `parse_expr` 内部会走 `eval`；`simplify` 的耗时也不可控。现在的做法是手写递归下降解析器（只认数字、已声明变量、四则与乘方、括号、几个函数），表达式等价靠在 6 个确定的取样点上比较数值。格式认不出、单位认不出、取样点不够时一律 `uncertain`。将来做主观题的步骤核验时再评估是否引入符号计算。

**10. "独立作答"的口径。** 只有会话里的第一份提交、且此前没有用过提示、图解、换种讲法或解析，才算独立。同一会话里的重试已经看过上一次的错因反馈，一律记为辅助。看图解也算辅助。

**11. 间隔复测。** 默认 T+1、T+3、T+7 天，`TUTOR_REVIEW_INTERVALS_MINUTES` 可配。答错或辅助答对的题进入队列；复测结果只取复测会话里第一份提交的服务端判定；复测会话在提交前不提供任何辅助。练习里独立答对不会跳过已经排好的复测。

**12. 今日任务不落库。** 每次按当前状态计算，任务 ID 由学生、日期、类别、题目推出，当天稳定。"跳过"留给客户端按任务 ID 在本地记录。薄弱点用的是最朴素的计数规则（某知识点上没有独立做对的次数多于独立做对的次数），只用来决定"再推一道"，不对外展示为掌握度。什么算"做过"：提交过作答，或者已经结束独立作答去看了解析；只是点开、画了几笔、看了提示就离开的，仍然留在今日任务里。（最初把"开过会话"都算做过，浏览器联调时发现点开任务再退出，它就从列表里消失了。）

**13. 题目列表在内存里排序分页。** 现在只有 17 道样题。题量上来之后必须改成数据库侧分页。

**14. 样题的 `published` 与 `reviewed` 标记。** 样题入库时状态为 published、解法 reviewed=True，只表示通过了 `content_seed.validate_seed` 的工程自检，不是 docs/07 要求的独立二审。接口里这些题带 `is_engineering_sample=true`，标签是"自编工程样题 · 未经学科审校"。

**15. 学生去标识化。** 发给网关和写进审计的是 `HMAC-SHA256(密钥, 用户 ID)` 的截断值。local 环境没配密钥时每次启动随机生成。

**16. 回环限制放在中间件。** 本地身份 Mock 开启时，非回环来源的任何请求在进入具体操作之前就被拒绝（403 `loopback_only`）。这条不逐个操作写进契约，在契约的总说明里交代。

## Flutter 学生端（apps/flutter_student）

### 版本与工程

Flutter 3.47.9 / Dart 3.13.7；flutter_riverpod 3.x、go_router 18.x、shared_preferences 2.5、flutter_math_fork 0.7、tutor_contracts（本仓库的 Dart 契约包，路径依赖）。`flutter create` 时用的是占位组织名 `com.example`，**上架前必须换成正式的应用标识**。

### 决策

**17. 契约包由生成器产出，手写的只有传输层。** `tools/gen_dart_contracts.py` 从 `openapi.yaml` 生成模型与客户端、从事件 Schema 生成各类 payload、从图解注册表生成模板表。遇到不认识的契约写法直接报错。枚举一律带 `$unknown`，契约里新增的值不会让旧客户端崩溃。`tools/export_dart_fixtures.py` 在进程内起后端、走一遍主流程，导出 42 个真实响应样例；Dart 契约包用它们做"解析再序列化必须与服务端 JSON 一致"的往返测试，Flutter 端的假后端也用它们，所以假后端的响应形状就是真的。Python 侧的 `test_dart_fixtures.py` 保证样例仍然符合当前契约。

**18. 应用层数据用 Riverpod，作答流程用 `ChangeNotifier`。** 登录、资料、今日任务、学情这类"取一份数据"的状态是 `AsyncNotifier`/`FutureProvider`。作答流程（`SolveController`）有定时器、同步队列、幂等键和页面生命周期，用普通类更直接，也能脱离界面做单元测试。`ProviderScope` 关闭了自动重试：断网由各页面自己处理并给"重试"，不在后台悄悄反复请求。

**19. 本地存储用 shared_preferences，键按用户 ID 分开。** 每个键整体写入。草稿格式带版本号；读不懂的草稿不丢，原文另存一份。这个选择对长笔迹不理想（Android 上启动时会把全部偏好读进内存），草稿体积超过约 1 MB 的场景要换成 SQLite 或 Isar——触发条件是真机上 10 分钟连续书写的实测数据。

**20. 草稿"先本机、后云端"。** 每次改动后 2 秒内落本机（切后台立即落），停笔 4 秒后同步云端；同步带 `base_revision`，幂等键含内容摘要。冲突（409）时不覆盖任何一方：同时显示两边的内容摘要，让学生选"保留我的"或"用云端的"；云端内容恰好与本地一致时（例如上次同步成功但响应丢了）静默对上版本。docs/03 要求的第三个选项"创建副本"没有做——服务端一个会话同时只允许一份未提交作答，副本需要先改后端。

**21. 墨迹按"页面逻辑坐标"存。** 每页 1000×1400，所以拖动分栏、旋转屏幕都不会让笔迹错位；每个采样点是 x、y、时间、压力。橡皮是"整条笔画擦除"，撤销栈用前后快照，上限 100 步。手写笔和鼠标直接书写，见过手写笔之后手指不再书写（防手掌误触），"移动"工具下任何输入都只滚动。压力目前只记录、不影响线宽。每帧重绘全部笔画，没有做光栅缓存——笔画很多时需要优化。

**22. 图解的绘制与计算分开。** 六个模板的 `CustomPainter` 只负责画，数值（顶点、受力分解、位移、化学计量换算、区间记号）在纯函数里算，各有单元测试。所有参数先经注册表补齐并收进边界，拖动滑块不请求网络。不认识的模板显示审核过的文字说明。

**23. 公式用 flutter_math_fork 渲染。** 样题里 203 段 LaTeX 全部有测试确认能被解析。解析失败时显示源码，不白屏；比可用宽度还宽的公式（窄屏、放大字体）等比缩小。读屏软件读到的是 LaTeX 源码，公式的朗读还没有专门处理。

**24. `flutter analyze` 在含中文的路径下会崩溃**（flutter_tools 的 LSP 消息长度按字符而不是字节计算）。改用 `dart analyze`，两者检查的规则相同。`flutter test` 与 `flutter build web` 不受影响。

**25. 中文字体打进应用。** 第一次在 Chrome 里联调时，所有中文都是方块：Flutter 的 Web 版（CanvasKit）渲染中文要联网下载回退字体，网络受限时下载失败。Android 与 iOS 用系统字体，不受影响，但 Web 版是本地联调的主要手段。解决办法是把 Noto Sans SC（SIL OFL 1.1，允许打包与裁剪）裁剪成子集打进资源：GB2312 一级汉字 3755 个 + ASCII、标点、希腊字母、数学符号、箭头 + 仓库里实际出现过的所有字符，共 0.87 MB。`tools/build_cjk_font.py` 可复现（源字体的 SHA-256 已固定），`tests/app/test_cjk_font.py` 保证界面和样题里的每个汉字都在子集里——将来题库出现了一级字表之外的生僻字，测试会失败并提示重新生成。主题和图解画布里自绘的文字都带了这个回退字体。只有常规字重，粗体是合成的。

### 浏览器联调（2026-11-11）

把 Web 发布版（`flutter build web --release`，静态服务 127.0.0.1:8081）接到真实的本地后端（`tools/run_dev_api.py`，127.0.0.1:8000），在 Chrome 里用 1024×768 视口走了一遍主流程：引导三步（四川 → 高三 → 教材"暂不清楚"）→ 首页三项任务 → 数学题作答页（选 A、用鼠标在草稿区画两笔、"给点提示"第 1 层、"看图理解"拖滑块、提交）→ 判错反馈 → "常规解法"→"我懂了"→ 排上明天的复测，回到首页后任务变成"变式"和"薄弱点" → 练习列表、错题复习、学情、我的。后端日志里所有请求都是 2xx：身份创建 201、资料读写 200、今日任务 200、题目 200、开会话 201、建作答 201、草稿同步 200。

联调发现并已修复（各有回归测试）：

1. 中文全是方块 → 决策 25。
2. 作答页标题栏有**两个返回箭头**（`AppBar` 自带一个，页面标题里又放了一个；Widget 测试直接构造页面，没有上一页，所以没有暴露）。现在关掉 `AppBar` 自带的，保留页面标题里的——它在没有上一页时会回首页。
3. "常规解法"底部的**方法要点标签显示的是公式源码**（`$x=-\dfrac{b}{2a}$`），因为标签用的是纯文本。`InfoChip` 现在经 `MathText` 渲染，没有公式时仍是普通 `Text`。
4. 二次函数图解里，开口向下时顶点在最高处，"顶点 (x, y)"标签贴着上沿，和"递增/递减"区间标签挤在一起。现在开口向下时区间标签改放下沿（位置规则是纯函数 `bandLabelsOnTop`，有单元测试）。
5. 手机宽度（375）下，首页的"拍题/练习/我的"三张入口卡只有 220 宽、靠左，没有铺满一行。现在手机宽度下铺满，平板竖屏等中等宽度仍然是 220 宽并排。
6. **后端：点开任务又退出，任务就从今日任务里消失了。** 见决策 12。后端测试里原来有一条断言把这种行为固定了下来（"开了会话就不再推荐"），现在改成"提交之后才不再推荐"。
7. **公式与旁边的文字在系统字体放大时比例不一致**：只有公式放大，旁边的文字原地不动（1.5 倍时整段宽度只变宽 1.09 倍而不是 1.5 倍）。原因是段落关了系统缩放、由公式自己乘倍数，普通文字漏了。现在统一由段落缩放。这条不是浏览器里看出来的，是联调时读代码发现、再用测试证实的。

这次联调**没有覆盖**：用手写笔或手指书写（只用了鼠标，笔迹是直线）、断网与草稿冲突（只在 Widget 测试里验证）、1024 宽以外的版式。另外，操作浏览器面板时若切换过"模拟视口大小"，Flutter Web 会保留旧的布局尺寸，需要重新加载页面才恢复；这是模拟的副作用，不是应用问题。

### 没有验证过的东西（Flutter 部分）

- **没有在任何真机或模拟器上运行过。** 开发机上 Android SDK 缺 cmdline-tools、没有 Xcode；`android/` 与 `ios/` 只是 `flutter create` 的脚手架，没有构建过。验证只在 Flutter 测试框架里和 Chrome 里做了。
- **手写体验没有实测**：10 分钟连续书写的延迟与误触、手写笔压力、不同厂商手写笔的事件类型（`stylus` 与 `invertedStylus` 的上报是否如预期）都是按规范写的，没有设备验证。
- **物理、化学图解的数值与示意没有学科老师看过**：受力示意、v–t 图、计量换算的公式都有测试对照，但图形表达是否合适需要审校。
- **无障碍**只做了语义标签、触控目标、对比度（Material 3 色板）和焦点；没有用真实的读屏软件走过流程。

## 原始题库（docs/ 下的高考真题文件）

2026-11-10 起 `docs/` 下多了约 8.4 GB、11,663 个文件的高考真题（数学、物理、化学、生物，1990–2026，PDF / DOC / DOCX）和课程标准。本切片没有导入它们，后端用的仍然是自编样题。原因有三条：

1. **格式。** 抽查近年的 DOCX：题干里的公式几乎全部是图片或嵌入的公式对象（一份空白卷里 130～160 个），不是文本。不做公式识别就得不到可判分的结构化题目。这正是 PRD 里后置到 P1 的"试卷批量切题"，需要 OCR / 图文模型，而真实模型调用目前是禁用的（Q-04A）。
2. **授权。** 这些文件的版权和可用范围是未冻结的决策（Q-05），解析卷里的解析还属于整理方。docs/07 只允许没有合法使用依据的材料用于内部核验。
