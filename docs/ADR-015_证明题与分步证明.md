# ADR-015 证明题：已知与求证、分步书写（每步带依据）、不评分、提交后对照参考证明

状态：已采纳（2026-11-15）。范围：PRD §5"数学解答/证明：手写步骤+小问 | 证明前提、逻辑链、分步 Rubric | 不夸大自动给分精度"和 §4.1"证明题逻辑链"
这一块的诚实版本——学生能读"已知 / 求证"，把证明写成一步一步（每一步写上依据），提交之后把自己的证明和参考证明并排对照；**不自动评分**。
后端、契约、Flutter 学生端、审核后台都有改动；**没有迁移**（已知、求证和参考证明存在题目版本的 JSON 列里）。

## 为什么还是"不评分"

和 ADR-011、ADR-013 同一个理由：Q-06（主观题评分细则及人工复核流程）没有冻结，原型阶段的处理方式是"低置信度弃判，不冒充官方阅卷"。
证明题比解答题更不能靠比对来评：同一个结论可以用不同的构造、不同的顺序证出来，"和参考证明像不像"跟"证得对不对"没有关系；
把一个写法不同的正确证明记成"错题"再去排复测，比不评分更糟。所以这一版和前两种主观题一样：系统如实说"这道题不自动评分"，
把**参考证明放在学生写的证明旁边**，再给一张按证明阶段分组、不带分值的要点清单，由学生自己对照。

## 决策

**1. 题面。** `QuestionContent` 新增 `proof`：`{givens, claim}`，非证明题为 `null`。
- `givens`：已知条件列表（0~8 条，每条 1~400 字）。界面上编号成 ①②③，学生写依据时可以说"由已知①"。题干里已经写全了已知条件时可以是空列表。
- `claim`：求证的结论（1~500 字）。
- `stem` 仍然必填，写题目的背景（"设 $a$、$b$ 是正数"）；已知和求证单列，是为了让界面把它们分开摆、写证明时能随时看到要证什么。
- 参考证明不在题面里，只在提交之后随自查给出。选择题、填空题、解答题、实验题带了 `proof`，程序校验会指出来。

**2. 作答形状。** `AnswerPayload` 新增 `steps: [{text, reason}]`（至多 30 步）。`text` 是这一步写了什么、推出了什么（至多 1000 字），
`reason` 是依据——定义、定理、已知条件或前面的某一步（至多 400 字）。列表的顺序就是证明的顺序。
证明题只用 `steps`：同时带 `selected_options` / `blanks` / `text` / `parts` / `cells` 返回 422（`field: answer`）；别的题型带 `steps` 同样 422。
**提交必须有内容**：至少一步有文字、或草稿里有笔迹（规则同解答题），否则 422（`field: answer`）。依据可以不写——写不写、写得对不对，
都不拦提交，也不判，只是界面上提醒"每一步写上依据，证明才完整"，并且在自查要点里问。没有文字的步骤原样存下，但不算"有内容"。

**3. 评估结果。** 与解答题、实验题完全一致：`state=pending`、`outcome=undetermined`、`is_correct=null`、`review_required=true`、`feedback` 为空，
会话事件是 `uncertainty`，`reason_code=subjective_self_check`（教学事件 Schema 不用改）。**和参考证明一字不差也不判对**——有单测专门守着。
证明题不进任何正确率分母、不排复测、不参与"薄弱点"判断，也**不算"没能判定"**。`grading.SUBJECTIVE_MODES` 现在是
`("written", "experiment", "proof")`：自查、今日任务的排序、学情、家长周报都引用它，所以这三处没有为证明题单独改判断。

**4. 对照自查。** 沿用 `GET` / `PUT /attempts/{attempt_id}/self-check`（解答题、实验题、证明题都能用，别的题型 409 `self_check_not_applicable`）。
`SelfCheck` 新增 `reference_steps: [{stage, text, reason}]`：参考证明，**只在作答提交之后才给**（提交之前 409 `attempt_not_submitted`，和要点同一道门），
取自**会话开始时固定的那个题目版本**；其他题型为空数组。`stage` 是这一步在证明里的角色，四选一：
`premise`（前提：用了哪些已知条件）、`construction`（构造：引入辅助量、辅助线，或把式子改写成便于证明的形式）、
`reasoning`（推理：一步一步推下去的关键步骤）、`conclusion`（结论：回到求证）。这四个阶段对应 docs/06 里"拆解前提、构造、关键变形、结论"。
`rubric.points[].part` 在证明题里是这四个阶段之一，或 `null`（针对整份证明，比如"每一步都有依据"）——自查清单因此按阶段分组，就是 PRD 说的"分步 Rubric"。
**不是评分**：参考证明只让学生并排看，要点仍然只有 `key / part / text`，响应里仍是同一句 `disclaimer`，`summary` 仍然只有三档的个数。

**5. 题库与程序校验。** `services/api/seed/questions/proof.yaml`：数学三道（证明一个含分式的不等式、用定义证明函数在区间上单调递增、证明同向的正数不等式可以相乘），
物理一道（由牛顿第二定律和运动学公式推导动能定理）；都是 `type: proof`、`answer_mode: proof`。三道数学题各用一个现有的知识点
（基本不等式、函数的单调性、不等式的基本性质），没有为证明题新增知识点（等比数列的证明这类题等有了对应的知识点再加）。化学没有收录：高中化学没有"证明"这种题型，
化学的"推断"另算（PRD §5 的 `inference`），这里不硬凑。`answer.value` 是 `{steps: [...]}`，每步 `{stage, text, reason}`。
`content_seed._check_proof` 是入库与审核后台共用的程序校验：

- `content.proof` 必须有、只有 `givens` 和 `claim` 两项，长度合规；不能有选项、空位、小问、数据表、安全提示；
- 参考证明至少 2 步、至多 20 步；每步 `stage` 合法、`text` 和 `reason` 都不能为空（**参考证明自己要示范"每一步有依据"**）；**最后一步必须是 `conclusion`**；
- 要点只有 `key/part/text` 三个字段（带分值会被指出来）；`part` 只能是四个阶段之一或 `null`；**参考证明里出现过的每个阶段至少有一条要点**；
- **必须自己列泄题标记**：证明的关键构造和关键变形没法自动推出来，提示里不能把它们直接写出来。
  样题的提示只给方向（"先看左边减右边是正还是负""分子能变成什么样的式子，符号能不能一眼看出来"），不给式子。

样题的内容靠独立重算核对：含分式的不等式那道用精确分数在网格上验证"差恒等于 $(a-b)^2/(ab)$、差非负、等号只在 $a=b$ 时取到"；单调性那道验证
$f(x_1)-f(x_2)=(x_1-x_2)(x_1x_2-1)/(x_1x_2)$ 以及"当 $1\le x_1<x_2$ 时 $x_1x_2>1$"，并验证区间左端点 $1$ 就是分界（往左伸进 $(0,1)$，结论不成立：$f(\tfrac12)>f(1)$）；
同向不等式相乘那道在整数网格上验证 $ac>bc$、$bc>bd$、$ac>bd$，并验证去掉"都是正数"之后结论不成立（$2>1$、$-1>-2$，可是 $2\cdot(-1)$ 并不大于 $1\cdot(-2)$）；
物理那道用精确分数验证速度—位移公式和 $Fs=\tfrac12mv_2^2-\tfrac12mv_1^2$。这只能保证式子自洽、每个"所以"站得住，**没有学科审校**；文字写得好不好、步骤切得合不合理要靠学科老师审。

**6. 学情、今日任务。** `ProgressSummary.subjective` 现在数解答题、实验题、证明题三种（字段名不变，改名是破坏性变更，只改了描述）：`attempts`、`self_checked`、
三档要点各有几条；仍然没有比例。家长周报的 `written_attempts` 同理，只说提交了几份。`estimated_minutes`：证明题 `9 + 3×难度`（要想构造、要写依据）；
新题和薄弱点补练仍然**先推可以自动判定的题**，三种主观题排在后面；练习页的题型筛选新增"证明题"。

**7. Flutter 学生端。** 题干下面是"已知"（①②③）和"求证"两块。作答区是"证明步骤"：每一步一张卡片，上面是"这一步写什么"，下面是"依据"，
卡片右上角有上移、下移、删除；最下面是"添加一步"。一开始有一张空白的卡片，最多 30 步；写证明的人可以随时在右边的草稿画布上写。符号条用的是解答题那个组件，
符号换成了证明里常用的（∵ ∴ ≤ ≥ ≠ ∈ ∠ ⊥ ∥ △ 等），插到当前聚焦的那个输入框（文字框或依据框）。**步骤随草稿一起先落本机、再同步云端**（`LocalDraft.steps`，旧版本存下的草稿没有这一项也能读，只有步骤、没有别的内容也算有内容）。
提交之后步骤变成只读、页面自动滚到"对照要点自查"卡片：最上面是**"对照参考证明"——"你的证明"和"参考证明"两列**（窄屏上下排），参考证明的每一步带阶段标签；
这里**没有对勾、没有红绿色、不说"对了""错了"**，只写一句"参考证明只是一种写法，你的证明不必和它一样；对照时看每一步有没有依据、前后接不接得上"。
要点按阶段分组（前提 / 构造 / 推理 / 结论 / 整份证明）。学情页的块改名"解答题、实验题和证明题"，家长周报里同理。

**8. 审核后台。** 审核页显示已知、求证、参考证明（每步的阶段、文字、依据）、按阶段分组的自查要点；编辑器里已知条件是一组文本框、求证是一个文本框，
参考证明是一组行（阶段下拉、文字、依据），要点的"所属"下拉是四个阶段加"整份证明"；版本对比把已知、求证、参考证明、要点逐行对比（参考证明一步一行："第 N 步｜阶段｜文字｜依据"，不会被摊成 `[object Object]`）。
"保存时不做程序校验"的原则不变，结果在保存后的"程序校验"里。

**9. 参考证明和标准解法是两份。** 标准解法（`solutions.standard`，纯文字的步骤和结论）仍然每道题都要有：它是学生**主动选择**看完整解析时给的（记 `used_solution`）。
参考证明是结构化的（阶段、文字、依据），专门给提交之后的并排对照用，不记 `used_solution`——提交之后独立性早已定下，和实验题的参考数据是同一个道理。
两份各自编写，没有程序保证它们说的是同一个证明，靠审核员判断。

**10. 顺带修的一处。** 学生端对账（`_reconcileDraft`）判断"本机有没有内容"时漏掉了实验题的格子；这次补上了格子和证明步骤。
学情页和家长周报里那一块的名字，从"解答题和实验题"改成"解答题、实验题和证明题"。

## 没做、没验证的

- **没有任何自动评分**：不比对步骤、不检查依据对不对、不识别手写、不调用模型。以后要做，需要 Q-06 冻结评分细则与人工复核流程，再经模型网关接入，并且遵守同一条原则——低置信度弃判。
- **参考证明只有一种写法**。证明往往有好几种对的写法，学生只能自己判断"我的和它不一样，但对不对"。docs/07 要求的"替代解法得分点"没有做成结构化的东西；
  现在只有一句提醒"证明的写法不止一种"，要点要写得对两种写法都适用，靠审核员。
- **阶段只标在参考证明上**。学生写的步骤没有阶段（不让学生给自己的步骤选"这是构造"），所以"你的哪一步是构造"要学生自己对照着看。
- **依据是自由文本，没有结构化引用**："由已知①""由第 2 步"只是文字，系统不检查有没有这一条、对不对得上；已知的 ①②③ 编号只在界面上。
- **没有图和图示**：立体几何、解析几何的证明需要图。契约里有 `attachments`，但学生端和审核后台都没有渲染它（同 ADR-013）；三道数学样题都是代数证明，物理那道是推导。
- **没有数学归纳法之类的专门模板**（基础、假设、递推、结论）：四个阶段可以勉强表达，但不是专门的结构。
- **化学没有证明题**；样题数学三道、物理一道，不构成覆盖，数据和讲法都是工程编的，**没有学科审校**。
- **学生写的步骤没有公式预览**：输入框是纯文本，符号条帮忙输入符号；参考证明里的公式才排版成公式。
- **步骤没有"撤销删除"**：删掉一步就没了（本机草稿也是按删之后的样子存的）。
- **自查的标记仍然没有落本机**（同 ADR-011）。
- 升级前缓存在本机的题目：缺 `data_tables` 的（实验题之前缓存的）仍然读不懂、按"没有缓存"处理；**只缺 `proof` 的（实验题之后、证明题之前缓存的）仍然读得出来**，已知和求证是空。
- 审核后台里证明题只有后端接口测试和组件测试，**没有浏览器联调脚本**（`tools/e2e` 只有学生端的 `student_proof`）。
- 字体放大、手机宽度在真实浏览器里的表现没验证（只有 Widget 测试）；鼠标滚轮和触摸滚动、读屏软件、真机都没验证。
- Flutter 只在测试框架和 Chrome（无头）里验证过；平板真机、Android、iOS 没有构建。
