# ADR-010 回看与对比旧版本

状态：已采纳（2026-11-12）。范围：ADR-009 留下的缺口——"旧版本留在库里，但审校员看不到"。
后端 `GET /admin/questions/{id}/versions/{version}`，审核后台的"版本对比"页。

## 决策

**1. 取某一版的完整内容。** `getQuestionVersion` 返回这个版本"可以被修改"的全部内容：标题、难度、年级、题面、答案、教学辅助、
解法（带这个版本**当时**的审核标记）、知识点、评分细则，加上是不是当前版本、提交者、保存时间。只有 reviewer 与 admin 可用，
和其他审核接口一样先检查角色再查资源；题目或版本不存在返回 404，版本号不是正整数返回 422。

**2. 难度、年级、知识点要补快照。** 题面、答案、教学辅助、解法、评分细则本来就按版本存；难度、年级在题目行上，知识点在关联表里，
修改题目会覆盖它们，旧版本的这三项就丢了。现在修改时把旧值记进旧版本、新值记进新版本（都放在 `question_versions.content_json` 里，
没有改表结构，所以没有新的迁移）。读某一版时：当前版本以题目现在的状态为准（二者一致）；旧版本用记下的快照；
**早于这个改动的旧版本没有快照，回退到题目现在的值**——只会发生在改动之前就改过的题上，本地原型库里没有这样的数据（演示库每次重建），
真实环境上线前也没有；测试里专门造了这种数据确认不会报错。

**3. 对比在前端算，后端只给快照。** 两个版本各取一份快照，在浏览器里对比。这样后端不用决定"怎样算改动"，
界面可以随时换展示方式（并排、行内、只看有改动的部分）而不动接口。差异计算是纯函数（`src/diff.ts`、`src/compare.ts`）：
文本按字/词做最长公共子序列（汉字一个字一块，英文数字连成词），先去掉两头相同的部分；列表按项做最长公共子序列，
相邻的"删一项、加一项"配成"改了一项"再对这一对做文本对比；对象类的内容（判定规则、单位规则、图解、评分细则）摊成排好键序的 JSON，逐行对比。
规模超过上限（元素个数之积 200 万）时放弃细分、整段当作换掉了，免得页面卡死——测试里用 8000 字的两段完全不同的文本确认 2 秒内返回。

**4. 对比页。** `#/questions/:id/compare?from=&to=`：选两个版本（下拉里写着版本号、提交者、时间），默认对比上一版与当前版本，
只显示有改动的部分和字段；勾选"显示没有改动的部分"（地址里是 `all=1`）显示全部；两边选同一个版本就是"回看这一版的完整内容"。
文本字段左边标出删掉的片段（红底划线）、右边标出新加的（绿底），含 `$公式$` 的字段再渲染一份公式；
解法的"审核标记"也参与对比（"已审核 / 未审核 / 没有这种解法"），这样能看出"这一版的快速解法被确认了没有"。
地址里的版本号乱写会回退到默认；版本不存在显示说明。

**5. 入口。** 题目页的版本徽章是链接（点开看那一版的完整内容）；有多个版本时有"对比最近两个版本"；
审核历史里的"修改"条目带"与上一版对比"；保存新版本之后的提示条里有"查看这次改了什么"。

## 没做、没验证的

- 只能两两对比，没有版本之间的"时间线动画"或三方对比；对比结果不能导出。
- 地区适用标记、来源信息不在对比里（它们不分版本）；小问和附件只按 JSON 行对比，没有可视化。
- 文本对比是字/词级的，没有处理"整段挪动位置"（挪动会显示成删一段、加一段）。
- 公式的对比是对 LaTeX 源码做的，改了半个公式时红绿标在源码上，下面再渲染两边完整的公式供对照，没有渲染出来的差异。
- 在浏览器里用真实后端走过：改一道待审题（标题、难度、年级、题干）→ 保存 → "查看这次改了什么" → 并排对比 →
  勾选显示全部 → 回到题目页看版本链接。第 1 版的难度和年级是修改前的值，说明快照回填在真实流程里生效。
  没有走过：三个以上版本之间切换对比、很长的题目的显示效果。
- 测试：后端 `tests/api/test_admin_version_snapshots.py` 27 项（含 20 道样题逐道与详情一致）；后台 `diff.test.ts` 16 项、
  `compare.test.ts` 11 项、`compareView.test.ts` 11 项；变异检查新增 2 条（修改时没记下旧版本的难度年级知识点、取某一版总是返回当前版本）。
