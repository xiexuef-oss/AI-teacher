# ADR-018 生产运行依赖与迁移边界

日期：2026-11-15。状态：实施设计；不表示生产环境可用。

## 当前证据

PROD-301盘点确认，运行引擎只允许SQLite；应用启动无条件create_all，原型身份、幂等和导入表均注册在同一metadata。
身份有Provider协议，但工厂仅选择本地Mock或Disabled；媒体API仍为501。
Redis/MinIO仅有开发Compose配置，没有运行适配；真实MySQL反射校验尚未覆盖完整约束与类型。
不能通过修改DATABASE_URL把当前原型当成生产部署。

## 分步实施

1. 明确运行依赖注入与启动校验，保持local原型兼容；非local不自动建表、写样题或回退proto存储。
2. 分离SQLite/MySQL连接配置，迁移只追加；独立迁移执行器记录版本与校验和，验证约束、索引、UTC毫秒精度、空库与升级链。
3. 数据库保存原子业务回执；Redis承担协调锁、租约、限流与可重建缓存，不能作为唯一执行成功凭据。
4. 媒体先做本地fake适配及归属元数据、受控对象键、临时上传确认、摘要校验、幂等删除和孤儿清理。
5. 身份先实现可注入适配和失效/撤销token边界；真实登录、刷新、监护核验由Q-03决定，保留学生主动授权与立即撤销。
6. 容器/CI、liveness/readiness、迁移发布、审计脱敏、备份恢复演练准备完成后，再验收真实部署。

## 一致性验收

- 业务提交后Redis丢失，重试仍不得重复执行；锁过期后旧owner不得覆盖新owner。
- 同邀请码不同家长并发兑换，只能一个成功；角色优先、统一404与授权最小化保持。
- 并发预算计数采用数据库原子增量，首次建行竞争不丢请求与估算费用；这不代表预算额度预占已具备严格并发上限。
- `proto_`表不进入生产迁移，不回写历史SQL；已有草稿、审计和逐题成功映射不得因切换丢失。
- SQLite单元测试不能作为MySQL运行验证；静态迁移通过不能作为真实恢复演练。
