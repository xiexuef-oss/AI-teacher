# ADR-014 联调脚本进仓库

状态：已采纳（2026-11-15）。范围：把此前一直是一次性的浏览器联调脚本，整理成仓库里可以重复运行的工具 `tools/e2e/`。
**不改任何产品行为**：没有契约、后端、客户端、迁移的改动，只加了工具、一个可选依赖组、一组不需要浏览器的单元测试和文档。

## 为什么

前几个功能（ADR-007 的首次联调、ADR-011 解答题、ADR-012 家长周报、ADR-013 实验题）都在真实的后端 + Flutter Web 发布版 +
无头 Chromium 上走过一遍，每次都把脚本写在临时目录里、用完即弃。ADR-012 因此写着：联调脚本没有进仓库，
这一层没有可重复运行的回归，只有当时记录的那一次。而这一层抓到过 Widget 测试和 API 测试都抓不到的东西——
页面和真实服务端对不上的那类问题（ADR-007、ADR-012、ADR-013 里各有记录）。每个新功能都要把这些脚本重写一遍，
成本高，也没有办法在改了别的地方之后确认老流程还通。

## 决策

**1. 位置与入口。** `tools/e2e/`：入口 `run.py`，流程在 `flows/`，公共部分在 `browser.py`（Flutter Web 的元素怎么找、
文字怎么读）、`servers.py`（起服务、判断构建是否过期）、`data.py`（从样题取数）、`api_client.py`（造数据）、`checks.py`
（检查汇总）。命令行：`--list`、`--only <流程…>`、`--no-build`、`--headed`、`--flutter <路径>`。
退出码 0 全部通过、1 有检查没通过、2 环境问题（缺依赖、端口被占、构建失败、浏览器起不来）。用法见 `tools/e2e/README.md`。

**2. 依赖：可选依赖组 `e2e`，钉死 `playwright==1.58.0`。** 和已有的 `mysql` 组一样，默认的 `uv sync` 不装，
跑联调时 `uv run --group e2e python tools/e2e/run.py`。钉死版本，是因为每个 playwright 版本对应固定的 Chromium 修订号：
1.58.0 与本机已经装好的浏览器对得上，不用再下载。换版本要重新 `playwright install chromium`。
`uv.lock` 多了 playwright、greenlet、pyee 三个包（+53 行）。浏览器本身不进仓库、也不自动下载。

**3. 固定端口，开始前检查。** 后端 8000（Flutter Web 版里把地址写死成了这个，`lib/config.dart`）、学生端静态服务 8081、
审核后台 5174（`vite.config.ts` 里 `strictPort`，后端本地环境只放行 localhost 来源的跨域）。三个端口被占就直接退出（码 2）
并说明，不去猜、不去杀别人的进程。代价是联调和本机的开发服务不能同时跑。

**4. 每条流程一个全新的数据库和一个新起的后端。** 数据库放在 `var/e2e/<流程名>/`，不碰本机的演示库；
流程之间不互相污染（审核后台的流程会把一道题下线、改版本，不该影响别的流程）。输出（后端日志、数据库、截图）都在 `var/e2e/`，
已被 .gitignore 忽略。学生和家长用不同的浏览器上下文，本机存储互相隔离。

**5. Web 版过期就自动重新构建。** 比较 `build/web/main.dart.js` 和 `lib/`、`assets/`、`web/`、`pubspec.*`、契约包 `lib/` 的修改时间。
过期的构建会让联调测到旧代码，给出"通过"的假象，所以默认不跳过；`--no-build` 是明知它没过期时才用。
这条判断是启发式的：不在上面那几个位置里的变化（比如依赖包的升级）不会触发重建。

**6. 数据从样题和测试的答案表里取，不重抄。** 标题、数据表、留空格子的参考值、要点数量、安全提示的条数、答案，
都从 `services/api/seed/` 和 `tests/support/flows.py` 取（`e2e.data`）。样题改了，联调跟着变；
改得让联调对不上，不需要浏览器的 `tests/unit/test_e2e_tooling.py`（41 项，随 `uv run pytest -q` 跑）会先红：
样题的标题和参考值、每道客观题的"正确"和"错误"答案是不是真的判成那样（逐题用 `grading.grade` 核对）、
周报计划里的客观题数够不够周报显示百分比（对照 `Settings().progress_min_samples`）、
流程的登记、以及"导入流程不需要 playwright"（所以 `--list` 和这些测试在没装浏览器的机器上也能跑）。

**7. 检查不用 assert。** `Checks` 一项一项记下 ✓ / ✗，一项不过不拦住后面的检查，最后汇总、给退出码；
流程里抛了异常也算一项失败，并给所有打开的页面各截一张图留作现场。

**8. 三条流程。**（后来又加了第四条 `student_proof`，见 ADR-015。）
- `student_experiment`（40 项）：此前实验题联调的那一条，期望值改成从样题推出来，多了几项（安全提示每一条都在、
  服务端的参考值就是样题里的参考值）。
- `admin_experiment`（37 项）：此前审核后台的那一条；队列数量从样题推出来（已发布的总数、其中实验题的数量），
  修了上次那条脚本里的三处问题（没翻完分页、读到上一步的旧提示、对比页的断言按字段而不是分节）。
- `parent_weekly`（54 项）：家长周报的那一条。**和此前的一次性脚本有一处不同**：第一份作答原来是在界面上点"今日任务"里的第一项、
  选 A（它错不错取决于今日任务的排序和样题的顺序），现在改成用后端接口按计划造 6 份（3 对、2 错、1 份解答题），
  周报里的数字（作答份数、独立正确率 3/5 = 60%、解答题和实验题 1 份）都从这份计划推出来。引导、授权、撤销、再授权、
  身份切换仍然走界面。

**9. 不是合并门禁。** 需要浏览器、Web 构建，全部流程约 8 分钟，仓库里也还没有 CI 流水线（ADR-007）。
AGENTS.md 的"命令"里列出了它，建议在改了学生端或审核后台的页面、流程之后跑一遍；要不要变成强制，是负责人的决定。

## 验证

- 不需要浏览器的部分：`tests/unit/test_e2e_tooling.py` 41 项，先写、先看它因为模块不存在而红，再实现。
  全量 `uv run pytest -q` 1356 项通过（此前 1315），`ruff check` / `ruff format` 通过。
- 在真实的浏览器里跑通：三条流程第一次跑就全部通过（40、37、54 项，共 131 项），没有 4xx/5xx 以外的意外响应、没有页面异常。
- **故意改坏三处，确认联调会变红**（改完都已还原）：
  ① 后端把实验题判成"正确"（`grading._grade_experiment` 返回 verified/correct）→ `student_experiment` 失败 2 项（"说明这道题不自动评分""没有判对错的措辞"）；
  ② 后端在审核后台修改实验题时丢掉安全提示（`review_service` 里写成 `"safety": None`）→ `admin_experiment` 失败 4 项：
  新版本的安全提示不是 3 条、新版本程序校验不过、对比页看不到新增的那条；后面又找不到安全级别的下拉框而超时——超时也被记成一项失败，并给页面截了图；
  ③ 学生端不显示实验安全提示卡（`solve_page.dart`）→ `student_experiment` 失败 2 项（安全提示不在题干下面、安全提示的每一条都不在）。
  第 ③ 处改的是 Dart 源码，联调自己先重新构建了 Web 版才测到它——顺带验证了"Web 版过期会自动重新构建"。
- **最后一轮全量联调是 129/131，两项是联调脚本的时序问题**：学生端流程里有两处输入丢了第一个字符（"2.00" 成了 ".00"、"T 等于…" 成了"等于…"）。
  Flutter Web 的输入框是点了才接上键盘的，点完马上输入会丢首字符——不是产品缺陷。新增 `browser.type_into`（点一下、等焦点落稳、再慢一点输入），
  所有往 Flutter 输入框里输入的地方都改用它。修复后学生端流程连跑 3 次都是 40/40，家长周报 54/54（审核后台的流程用 `fill`，不受影响，37/37）。
  这类时序问题只在机器忙的那一次露了出来，说明流程里固定的等待时间仍然是个风险（见下面"没做"的最后一条）。

## 没做、没验证的

- 只有 Chromium（无头、软件渲染）：没有 Safari/WebKit、没有真机、没有 TalkBack/VoiceOver。
- 只在 Windows 上跑过。`kill_tree` 的非 Windows 分支、路径和端口检查在 macOS/Linux 上没有验证。
- 没有接 CI；联调也没有并行跑（固定端口决定了不能）。
- 视口开得很高，一屏放得下整页，所以**没有覆盖滚动**；字体放大和手机宽度只由 Widget 测试覆盖。
- 解答题（`written`）没有单独的浏览器流程：它和实验题共用自查那一段，但"分小问作答"本身没有在浏览器里重复走。
- Flutter Web 上输入框的值读不到（语义输入框不回显没聚焦字段的值），所以"恢复了什么"靠提交请求体和截图证明，
  不能直接断言输入框里显示什么。
- 构建过期的判断是启发式的（见决策 5）；构建失败时只给出日志的最后几行，日志在 `var/e2e/flutter_build.log`。
- 流程里仍有不少固定的等待时间（`wait_for_timeout`）来等 Flutter 画完，慢的机器上可能需要调大。
