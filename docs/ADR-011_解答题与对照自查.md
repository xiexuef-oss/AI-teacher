# ADR-011 解答题（主观题）：作答、不评分、提交后对照自查

状态：已采纳（2026-11-13）。范围：PRD P0 第 3、4 条里"主观题"这一块的诚实版本——能写、能存、能对照参考要点自查，
**不自动评分**。后端、契约、迁移 003、Flutter 学生端、审核后台都有改动。

## 为什么是"不评分"

Q-06（主观题评分细则及人工复核流程）还没有冻结，原型阶段的处理方式写明是"低置信度弃判，不冒充官方阅卷"
（`docs/DECISIONS_PENDING.md`）。模型网关里只有 Mock，没有接任何外部模型，所以也没有"AI 评分"可言。
解答题的答案是一整段话：靠比对文字评对错一定会错判（写对了但写法不同），把错判记成"错题"再去排复测，比不评分更糟。
所以这一版只做一件事：学生写完提交，系统如实说"这道题不自动评分"，给一张**不带分值的要点清单**，由学生自己对照标"做到了 / 做到一部分 / 没做到"。

## 决策

**1. 作答形状。** `AnswerPayload` 新增 `parts: [{key, text}]`，`key` 是小问的键（`content.subquestions[].key`）。
解答题只用 `parts`：同时带 `selected_options` / `blanks` / `text` 返回 422；选择题和填空题带 `parts` 同样 422。
可以只写其中几问；每个 part 的文字至多 4000 字，同一个小问不能写两次，不能写题目里没有的小问。
**提交必须有文字或笔迹**：`parts` 全是空白、草稿里也没有笔迹，返回 422（`field: answer`）。笔迹随草稿同步，所以服务端看的是
`handwriting_drafts` 里有没有至少一笔（只有空白页不算）；客户端因此在"只有笔迹、没有文字"时要求草稿同步成功才允许提交，
不让服务端拒绝一个学生其实写过的答案。

**2. 评估结果。** `state=pending`、`outcome=undetermined`、`is_correct=null`、`review_required=true`，`feedback` 为空；
会话事件是一条 `uncertainty`，`reason_code=subjective_self_check`（`tutor_event.schema.json` 新增这个原因码），
`state_after=DIAGNOSED`。**哪怕和参考答案一字不差也不判对**——有单测专门守着。解答题不进任何正确率分母、不排复测、
不参与"薄弱点"判断；也**不算"没能判定"**：学情里的 `uncertain_attempts` 只数客观题的待确认。

**3. 对照自查。** 两个新接口 `GET` / `PUT /attempts/{attempt_id}/self-check`：
- 要点（`rubric.points`）**只在作答提交之后才给**：提交之前 409 `attempt_not_submitted`，独立作答阶段不泄题；
  不是解答题 409 `self_check_not_applicable`；题目、`QuestionOut`、今日任务等任何提交前的结构都走不到 `SelfCheckPoint`（契约测试沿 `$ref` 遍历守着）。
- `PUT` 整体替换：每个要点必须**恰好评一次**（漏评、重评、评不存在的要点都是 422），三档 `done / partial / missed`，
  带 `Idempotency-Key`，同一个键重放得到同一个结果、不同内容换同一个键 409；可以改了再存。
- 要点取自会话开始时固定的那个题目版本（`study_sessions.question_version`）：题目之后下线、修改、重新上线，不影响这份作答的自查。
- **不是评分**：要点只有 `key / part / text` 三项，没有分值；响应里有 `disclaimer`（"不是官方阅卷分数，也不会计入正确率"）；
  `summary` 只有三档的个数和总数，不折算成分数。保存自查不改变作答的评估，也不改变会话状态。
- 新表 `attempt_self_checks`（迁移 `003_subjective_self_check.sql`，只追加；001、002 不动）：一份作答一行，`marks_json` 存
  `[{point_key, level}]`，按要点清单的顺序存。

**4. 学情。** `ProgressSummary.subjective`：`attempts`（提交了几份）、`self_checked`（其中自查了几份）、`points_done / partial / missed`
（自查里各档要点各有几条，只统计已保存自查的作答，改了自评按最新的一次算，不累加）。**没有比例、没有正确率**；
`by_answer_mode` 仍然只有三个客观题型。

**5. 题库。** `services/api/seed/questions/written.yaml`：数学、物理、化学各一道解答题（`type: solution`、`answer_mode: written`），
各两个小问；每道题有参考答案（每个小问一段文字，只用来对照）、6~7 条自查要点、三层不泄题的提示、只有标准解法。
`content_seed._check_written` 是入库与审核后台共用的程序校验：至少一个小问且键唯一、小问的作答方式是 `written`、参考答案覆盖每个小问、
要点只有 `key/part/text` 三个字段（带分值会被指出来）、**每个小问至少有一条要点**、`part` 只能指向存在的小问（或 `null` 表示针对整份解答）、
**必须自己列泄题标记**（一段话的答案推不出自动标记）。选择题和填空题则不能带小问。
样题内容靠独立重算核对：数学用网格检查"在 `[1,+∞)` 上递增 ⇔ `a≤1`"和 `[0,3]` 上的最值；物理逐步算支持力、摩擦力、加速度，
并核对题目给的 `sin37°`、`cos37°` 与真值取一位小数一致；化学离子方程式在测试里逐项数原子和电荷。这只能保证自洽，**没有学科审校**。

**6. 今日任务。** `estimated_minutes`：解答题 `8 + 2×难度`，其余仍是 `3 + 难度`。新题和薄弱点补练**先推可以自动判定的题**，
解答题排在后面——第一次使用的学生不会被分到一道要写半页的题；练习页的题型筛选里新增了"解答题"，所以随时可以主动去做。

**7. Flutter 学生端。** 分小问输入框（每问一个多行框，下面是数学符号条；字体里没有的上下标没放进符号条）+ 右边的草稿画布；
草稿的分小问文字和笔迹一样先落本机、再同步云端（`LocalDraft.parts`，旧版本存下的草稿没有这一项也能读）。提交之后出现"对照要点自查"卡片：
按小问分组，每条三个选项（选中状态有勾和文字，不只靠颜色），标完才能保存，保存后只显示"做到了 N · 做到一部分 N · 没做到 N（共 N 条）"；
提交后页面自动滚到卡片顶部。时间线里是一张"这道题不自动评分"的说明卡，不是"待确认"。学情页多一块只有计数的"解答题"。

**8. 审核后台。** 审核页显示小问、按小问列出的参考答案、按小问分组的自查要点；编辑器里小问与参考答案是同一批行、要点是另一批行
（所属小问用下拉选，"整份解答"对应 `part: null`），评分细则里除 `points` 之外的内容原样保留；版本对比把小问、参考答案、要点逐行对比，
改了哪一条一眼能看出。"保存时不做程序校验"的原则不变，结果在保存后的"程序校验"里。

**9. 顺带修的一个生成器问题。** 契约里的多行描述（YAML 的 `|` 块）会让生成的 Dart 枚举注释漏出注释之外、编译不过；
现在枚举的描述和类的描述一样压成一行（`tools/gen_dart_contracts.py`），并有测试守着。

## 没做、没验证的

- **没有任何自动评分**：不比对文字、不识别手写、不调用模型。以后要做，需要 Q-06 冻结评分细则与人工复核流程，再经模型网关接入，
  并且遵守同一条原则——低置信度弃判。
- **自查的标记没有落本机**：学生标了一半就离开页面，没保存的标记会丢；已经保存到服务端的，换一次会话打开同一道题也看不到
  （没有"我的历史作答"页）。作答草稿的本机优先原则没有延伸到自查——它只是几下点选，丢了重标即可，这是有意的取舍，不是疏忽。
- **自查不影响任何学习安排**：自评"没做到"的要点不会自动进入复测队列、不会改变薄弱点判断——自评不是服务端核验的结果，
  而复测只认服务端核验的作答。以后可以做成"学生主动选择把这道题加入复习"。
- 手写笔迹没有任何识别；解答题只看"写没写"。证明题（`proof`）、实验题（`experiment`）没有做，实验题提交仍是 `pending`、且审核校验不允许上线。
- 样题没有学科审校；数学、物理、化学各一道，不构成覆盖。要点文字的好坏、分问是否合理要靠学科老师审。
- 小问的键被审核员改名后，原来指向它的要点会被程序校验指出来（"指向不存在的小问"），不会自动改写。
- 迁移 003 只做过静态解析和 ORM 对照，**没有在真实 MySQL 上执行**（与 001、002 一样）。
- Flutter 只在测试框架和 Chrome 里验证过；平板真机、Android、iOS 没有构建。在 Chrome 里用真实后端走过：引导 → 练习页筛"解答题" →
  作答（分小问输入）→ 提交 → 自动滚到自查卡片 → 逐条标记 → 保存 → 学情页出现只有计数的"解答题"块、正确率仍是"信息不足"；
  审核后台里走过：看解答题 → 下线 → 编辑（加一条要点、归到第 1 问）→ 保存成第 2 版 → 并排对比看到新加的那一行。
  这个浏览器面板是后台页面，滚轮和键盘滚动不生效，所以自查卡片的完整标记是把窗口拉高之后点的；没有验证过鼠标滚轮/触摸滚动。
- 手写（笔迹）单独提交，只有测试覆盖，没有在浏览器里实际画过。
