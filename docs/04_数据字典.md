# 04 数据库字典与一致性约定

单一数据库结构以 `migrations/001_init.sql` 为准（MySQL 8.0 / InnoDB / utf8mb4）。所有 ID UUID v4，存 `CHAR(36)`；时间 UTC `DATETIME(3)`；软删除/历史审计按需实现，学习记录不能因题库更新而无版本依据。

| 表 | 主键 | 功能 / 关键列 | 关键约束 |
|---|---|---|---|
| users | id | role, email_hash, display_name | 唯一非空 email_hash；身份映射可由后续 auth provider 增补 |
| student_profiles | user_id | grade, region, curriculum_version | 与 users 一对一 |
| parent_student_links | id | parent_id, student_id, consent_at | 仅明确授权、可撤销 |
| knowledge_nodes | id | subject, code, title | subject+code 唯一 |
| knowledge_edges | id | prereq_id, target_id | 禁自环、应用层检环 |
| questions | id | subject, type, answer_mode, status, version, source_license | 仅 published 可对学生正式分发 |
| question_versions | id | question_id, version, content_json, answer_json | (question_id,version) 唯一 |
| question_knowledge | ... | question_id, knowledge_id | 复合唯一 |
| solutions | id | question_id, version, kind, content_json, conditions_json | `fast` 需条件并审核 |
| rubrics | id | question_id, version, rubric_json | 评分规则与题目版本绑定 |
| study_sessions | id | student_id, question_id, question_version, state | 需记录快照版本 |
| attempts | id | session_id, status, answer_json, assisted, used_solution, submitted_at | request-id 幂等；独立与辅助区分 |
| handwriting_drafts | id | attempt_id, revision, strokes_json, media_key | 版本冲突不静默覆盖 |
| tutor_events | id | session_id, seq_no, event_json | 事件不可随意覆盖 |
| review_items | id | student_id, question_id, due_at, status | 复测调度，不以 AI 估算替代实测 |
| media_assets | id | owner_id, object_key, mime, sha256 | 私有对象、访问鉴权 |
| audit_logs | id | actor_id, action, target_type, target_id | 管理操作审计 |

### JSON 约束
`question_versions.content_json`：`stem`, `options[]`, `subquestions[]`, `attachments[]`；`answer_json`：`value`, `equivalence_rules`, `units`。提交答案 `attempts.answer_json` 保留各小问与步骤，以及模型读到的 OCR 校正记录。MySQL JSON 基础形状通过应用层 Pydantic 和自动测试双重校验，数据库不负责所有语义校验。

### 可追溯与安全
- 更新题干生成新 question_version，旧作答不重算默认成绩；删除数据遵循留存策略，父母关系撤销后立刻撤回访问权限。
- 未发表的 AI 生成内容不可直接派发为已核验高考真题；`source_license` 与 `source_year` 是独立字段。
- 只记录隐私必要日志，上传图像中可能存在姓名/学校信息应脱敏。数据生命周期/账户注销流程是上线前门禁。

### 迁移纪律
只追加 Alembic/SQL 迁移；已部署迁移不可回写；加索引、列迁移需含回滚/兼容策略；生产回滚优先应用回滚，数据迁移需备份与演练。
