# ADR-012 家长周报与学生授权

状态：已采纳（2026-11-13）。范围：PRD P0 第 8 条"家长周报基础版"、US-06；`docs/03` P10；`docs/05` 里的 `GET /parents/students/{id}/weekly`。
后端、契约、迁移 004、Flutter（家长页、学生"我的"里的"家长查看"）都有改动。

## 先说清楚：这不是对 Q-03 的回答

Q-03（登录方式与未成年人监护授权）没有冻结，`docs/DECISIONS_PENDING.md` 给的原型处理方式是"身份服务适配器 + Mock"。
这一版的家长是**本地身份 Mock 里的一个角色**，授权是**学生自己生成一次性邀请码、告诉家长、家长输入**——
它没有核验任何人是不是监护人，**没有任何年龄判断**（PRD 明确"不能仅凭年龄字段自行推定法定义务"），也不是真实账号。
界面上两边都写了"原型阶段，不是真实账号、没有监护人核验"。真实的授权方式要等 Q-03 冻结之后重做；
这里做对的是**授权之后能看到什么、看不到什么、怎么撤销**这些不依赖登录方式的规则，它们换了登录方式也该成立。

## 决策

**1. 授权是学生发起的、一次性的、可撤销的。**
- `POST /me/parent-invites`（学生，带 `Idempotency-Key`）生成十位邀请码，字母表去掉了 0 O 1 I L，约 50 位随机；默认 24 小时有效
  （`parent_invite_ttl_minutes`）。**明文只在这一次响应里出现**，库里只存 SHA-256（`parent_invites.code_hash`，迁移 004）；
  学生再生成一个，他之前没用掉的立刻作废；用过一次就作废。
- `POST /parents/links`（家长，带 `Idempotency-Key`）输入邀请码建立绑定。输入时空格、短横线、大小写都忽略。
  **邀请码不对、过期、用过、被顶替、学生已停用——一律 404 `invite_invalid`，同一句话**，不让人拿它试码。
  已经绑定着这位学生再输入另一个码是 409 `already_linked`，码不会被消耗。
- `consent_at` 是**邀请码生成的那一刻**（学生做出授权的时间），不是家长输入的时间；`linked_at` 才是绑定建立的时间。
  同一对家长和学生只有一行 `parent_student_links`：撤销之后重新授权，是把这一行重新打开，同意和绑定的时间都换成这一次的。
- `POST /me/parent-links/{link_id}/revoke`（学生，带 `Idempotency-Key`）撤销，**立即生效**。只有学生能撤销；别人的、不存在的、
  已经撤销过的授权都是 404。撤销用 POST 而不是 DELETE，是为了不去动本地开发的跨域方法白名单。
- `GET /me/parent-links` 给学生看自己授权过谁、有没有还没被用掉的邀请码（**只有 id 和有效期，拿不回邀请码**）。

**2. 家长只看汇总。** 家长能调用的只有三个接口：输入邀请码、`GET /parents/students`、`GET /parents/students/{id}/weekly`。
没有题目、没有作答内容、没有提示与解析原文、没有草稿和笔迹、没有每次练习的时间、没有知识点明细、没有错题。
契约测试沿 `$ref` 遍历，守着周报的响应里走不到这些结构（`test_what_a_parent_can_see_never_reaches_questions_answers_or_drafts`），
也守着没有排名、连续天数、每次练习的时间这类字段。

**3. 权限来自 token，防枚举。** 家长接口的**角色检查先于任何资源查询和请求体校验**（和审核接口一样）：学生调用是 403。
家长读一个学生，要求"绑定存在且没有撤销、学生是 active"；**没绑定、已撤销、学生不存在，三者都是 404，响应一模一样**。
周报的 `week_start` 校验放在授权之后：没授权的家长连"这个日期合不合法"都问不出来（有测试，也有变异）。

**4. 周报口径与学情页一致**（`progress_service` 被重构成可复用的几块，`summarize` 的行为没变，原有测试全过）。
- 一周是周一 00:00 到下周一 00:00（右开），按固定偏移划分（`report_utc_offset_minutes`，默认 480，首发地区四川、重庆都是 UTC+8；
  不查时区数据库，Windows 上没有）。`week_start` 缺省是当前这一周；必须是周一（否则 422），不能是还没开始的一周（422）。
- 字段：`sessions_count`（这一周开始的练习次数）、`attempts_count`（提交的作答）、`active_days`（有提交作答的天数，0–7，**不做连续天数**）、
  `independent` / `assisted` / `hint_dependency` / `retest_success` 四个 `RateStat`、`written_attempts`、`independent_trend`、`previous_week`、
  `by_subject`、`disclaimer`。只有确定判定的作答进比例；独立和辅助分开；**样本不足 `progress_min_samples`（5）时比例是 `null`，只给计数**；
  解答题只数提交了几份，**不进任何比例**（ADR-011）。
- 趋势 `independent_trend` 只比独立正确率：`up` / `down` 要差 5 个百分点以上，否则 `flat`；**任何一周样本不足就是 `unknown`**，
  不拿一个不可靠的数去比。界面上只用"比上一周高了 / 低了 / 和上一周差不多 / 暂时比不了"，图标旁边一定有字，也不用红绿色。
- `disclaimer`：练习反馈、不是官方成绩；样本少时是"信息不足"；周报只有汇总；解答题不自动评分。**没有排名、没有连续天数、没有对比别的学生。**

**5. 审计。** 生成邀请码、建立绑定、撤销各写一行 `audit_logs`（谁、什么时候、哪条授权），**不含邀请码**。

**6. 角色。** `LocalRole` 增加 `parent`；本地身份 Mock 的 `role=parent` 和 `reviewer` / `admin` 一样，只在本地环境、只接受回环地址。
`parent` 角色只有上面三个家长接口的权限：调用学生接口、审核接口都是 403。

**7. 契约与迁移。** 新增 6 个操作（`getParentWeekly` 从 `planned` 变成 `implemented`）；三个会改状态的动作都在"必须带幂等键"的清单里。
迁移 `004_parent_invites.sql` 只追加（001 里本来就有 `parent_student_links`）；ORM 与迁移的列一一对照。

**8. Flutter。**
- **身份**：`AuthSession` 带角色；本机存两个槽，当前身份在 `auth.*`，暂时不用的那个收在 `auth.other.*`。"我的"页的"切换到家长身份（本机演示）"
  和家长页的"切换到学生身份"互相切换，**切回去还是原来的那个身份**（学生的草稿按用户 ID 分开存，不会混）；另一个角色还没有身份时才去领新的；
  领不到（断网）就什么都不改、留在原页面并说明。登录失效后重新领身份**角色不变**。以前存下的、没有记角色的身份按学生处理。
- **页面与身份对不上**：`RequireAuth` 带角色。家长打开学生的页面、学生打开家长的页面，都只显示一句说明和一个去处，**一个请求也不发**。
  数据也按身份守着：学生的数据（资料、今日任务、复测、学情、授权列表……）从 `studentSessionProvider` 取，家长的数据从 `parentSessionProvider` 取，
  身份不对就直接抛 `WrongSession`——切身份的那一刻依赖旧身份的数据会立刻重算，不能让它们拿着另一个身份的凭据去请求（见下面的联调发现）。
- **与 `docs/03` 的偏差**：P10 只写了 `/parent/weekly`（unauthorized / empty / ready 三种状态，这三种都有）。家长要先有一位授权的学生才有周报可看，
  所以拆成两页：`/parent`（学生列表、输入邀请码）和 `/parent/weekly/:studentId`（周报）。
- **家长首页** `/parent`：说明（只看汇总、学生可以撤销、原型）、已授权的学生（没有称呼就显示"学生 + 编号前 8 位"）、输入邀请码、本机演示切换。
  **家长周报** `/parent/weekly/:studentId`：一周的起止、"这一周已经结束 / 还没结束（还没过完，数字还会变）"、上一周 / 下一周（当前这一周不能再往后翻）、
  三个计数（**有作答的天数**、**开始的练习**、**提交作答**——标签照着服务端真正数的东西起名）、四张比例卡（与学情页共用 `RateCard`）、
  趋势（只有"高了 / 低了 / 差不多 / 暂时比不了"，图标旁有字、不用红绿色）、解答题份数（说明不自动评分、不进比例）、按科目、免责声明、更新时间。
  这一周没有学习记录就明说、不当成出错；授权已经撤销只说明这一件事、页面上没有任何数据；网络出错给重试、不显示旧数据。
  内容贴着顶部排（`SingleChildScrollView` 会缩到内容的高度，外面套 `Center` 在高屏幕上会悬在中间）；直接打开周报页（刷新、深链）没有上一页时，返回键回家长首页。
- **学生的"家长查看"**（在"我的"页）：说明家长能看什么、看不到什么；授权列表（每行一个"撤销"，**先确认**）；生成邀请码的弹窗显示五位一组的十位码、
  有效期、"重新生成会让这一个失效"，**关掉就再也看不到**；还没用掉的邀请码只显示有效期。"称呼"字段（家长看周报时看到的名字，可以不填）和资料一起保存。
- **操作之后的反馈会被读屏软件读出来**：`Callout(announce: true)` 是 live region 的独立一块。联调里发现，不这样做的话，绑定成功的那句话会被并进旁边输入框的
  `aria-label`，出现时读屏软件不会读，用户只会看到输入框"变了"。
- **幂等键只用合法字符，不含任何用户输入**：`newIdempotencyKey` 把标签里不合格的字符换成 `_` 并截到 24 位；`PendingKeys.keyFor(action, label:)` 让动作名可以带邀请码、
  而键里只有 `redeem`。测试里的假后端现在和真服务端一样检查键的格式（`^[A-Za-z0-9._:-]{8,128}$`），所有页面的测试都受益。

## 浏览器联调（2026-11-13）：真实后端 + 发布版 Web

把 `flutter build web --release` 的产物（127.0.0.1:8081）接到真实的本地后端（127.0.0.1:8000，**全新的数据库**），学生和家长是两个互相隔离的浏览器上下文
（各自的本机存储）。**这次没有用应用内浏览器**：它所在的窗口被隐藏时页面一帧都不画（`requestAnimationFrame` 不触发，截图超时），Flutter Web 就没法跑；
改用本机已有的 Chromium（Playwright，无头），打开应用的无障碍语义树之后按角色和文字点按钮、输入、断言。CanvasKit 改从构建产物里读，不依赖外网。
脚本在本机临时目录里，**没有放进仓库**（仓库里没有 Playwright 依赖，也没有端到端测试这一层）。

走了一遍，**55 项检查全部通过**：学生引导 → 首页第一道题（选错）→ 用同一条后端路径补 4 份客观题和 1 份解答题 → "我的"页设置称呼 → 生成邀请码
（弹窗里是五位一组的十位码；关掉之后页面上哪里都找不到它；"我的"页显示有一个没用掉的邀请码）→ 家长（学生身份）打开 `/parent` 被挡住、
没有请求任何家长接口 → 从"我的"切到家长身份（没有任何 4xx/5xx）→ 输入邀请码（**小写、带空格**）绑定 → 家长页出现"小明" → 周报：
这一周起止、"还没结束"、有作答的天数 1 天、开始的练习 6 次、提交作答 6 份、独立正确率 60%（3/5）、辅助和复测"信息不足"、解答题 1 份（不自动评分）、
趋势"暂时比不了"、按科目、"不是官方成绩"，页面上没有任何题目文字 → 上一周（没有学习记录）→ 回到这一周 → 学生看到授权、撤销（**先确认**，取消后授权还在）→
家长刷新周报页：只说"授权已经撤销"，页面上没有任何数据，服务端是 404 → 家长首页上学生没有了 → 学生再生成一个码、家长重新授权（同一对重新打开）→
旧码：只说"邀请码不对，或者已经过期、已经被用过" → 家长切回学生身份，还是原来那个学生。整个过程里的非 2xx 响应只有两条，都是预期的 404。

**联调发现了四个只有真实后端和真实浏览器才暴露的问题**，都已修掉并补了回归测试（单元测试用的假后端看不出来）：

1. **邀请码被拼进了幂等键，带空格的码服务端直接 400。** 客户端用动作名（`redeem:<邀请码>`）给幂等键起前缀，家长照着分组写法输入 `ABCDE 23456` 时键里有了空格，
   服务端拒绝（`invalid_idempotency_key`）；而且邀请码是机密，不该出现在请求头和服务端日志里。现在键里没有任何用户输入，假后端也会检查格式。
2. **切身份的那一刻，旧页面拿着新身份的凭据重新请求数据，服务端 403。** 状态一换，`ref.watch(authProvider)` 的数据都会立刻重算，而页面要到下一帧才被换走。
   现在学生的数据和家长的数据各自从带角色检查的会话取，身份不对就直接失败、一个请求也不发（单元测试逐个读一遍，切身份的测试数请求数）。
3. **绑定成功的提示不会被读屏软件读出来**（见上，`announce`）。
4. **家长页的内容在高屏幕上垂直居中**，悬在中间。改为贴着顶部。

另外，错答之后的收尾流程（"先到这里"、"完成"）在第一次联调脚本里和对客观题答对的流程不一样，是脚本没处理，不是应用的问题。

## 没做、没验证的

- **没有真实的家长账号、没有监护人核验、没有年龄判断**（Q-03）。本地身份 Mock 的家长谁都能领；邀请码只证明"持有者得到了学生的授权"。
  未成年人的授权与数据处理要依法评估，这一版没有对此给出任何结论。
- **兑换接口没有限流**（`docs/05` §5 要求）：十位码约 50 位随机、24 小时、一次有效，本机原型够用；上线前必须补。
- **邀请码明文还留在原型的幂等记录里**：为了"同一个键重放得到同一个码"，`proto_idempotency_records` 存着完整响应。
  真实幂等存储替换 SQLite 原型时（README"下一步"第 3 条）要同时处理，例如只存摘要、重放时让学生重新生成。
- 家长不能自己解除绑定，只有学生能撤销；没有"家长最近看过什么"的透明记录（学生看不到家长什么时候看过周报）；学生那边的授权列表不会在家长绑定的那一刻自己刷新，重新进入"我的"页才看到。
- 周报没有知识点明细、没有错题——有意的取舍，不是遗漏；也没有推送、邮件、微信，家长要自己打开。
- "称呼"一旦设置就清不掉：接口里 `display_name` 缺省或 `null` 都表示"不改"（生成的 Dart 客户端也没法发出显式的 `null`）。
- 一周的边界用固定偏移，不处理夏令时、不按学生所在时区变；首发地区都是 UTC+8，所以现在没有差别。
- 迁移 004 只做过静态解析和 ORM 对照，**没有在真实 MySQL 上执行**（与 001–003 一样）。
- Flutter 只在测试框架和 Chrome（无头）里验证过；平板真机、Android、iOS 没有构建。联调脚本当时没有进仓库（后来进了，见 ADR-014 的 `parent_weekly` 流程），所以当时这一层没有可重复运行的回归，
  只有上面记录的这一次。读屏软件（TalkBack、VoiceOver）没有真机试过，只检查了语义树里有没有 live region。
- 学生和家长在同一台设备上来回切换时的本机存储，只在测试框架（内存存储）和浏览器的 localStorage 里验证过；`shared_preferences` 在 Android、iOS 上的行为没有试过。
- 浏览器里家长页的触摸滚动、鼠标滚轮没有验证（联调时把视口拉高，页面一屏放得下）。
