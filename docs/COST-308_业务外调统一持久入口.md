# COST-308 业务外调统一持久入口

2026-11-17。复用 PROD-302 / COST-302 的持久调用状态机，不新增账本、迁移或公开 API。

后续[COST-310](COST-310_独立SDK持久调用.md)已为独立SDK增加显式持久单次绑定；本篇以下描述的是COST-308当时边界。默认未绑定行为未改变，多尝试/正文恢复和真实账单对账仍未完成。

## 已实现

应用配置允许外调，或注入的 ModelGateway 允许外调时，启动必须显式开启持久模型调用，
并满足既有的稳定去标识密钥、正式 SQL 回执及数据库结构检查。
此项检查依据外调开关意图，不依据当前候选是否启用、环境变量是否齐全或熔断器状态；
避免候选暂时不可用时绕过检查、稍后恢复可用后进入旧入口。

启动接线对应用持有的 ModelGateway 施加单向策略：旧 invoke 跳过外部候选，仍可使用
本地候选；单次调用 seam 保留给已有持久编排器。旧入口在重试退避后和预算提交后重新
检查这项策略，避免 IO 间隙切换配置造成发送。未通过准入的外部候选不消耗请求槽。

独立使用的网关 SDK 保持既有行为；它没有因此获得持久恢复能力。业务调用必须经过
编排器，不应直接构造 single-attempt plan 绕过持久 dispatch。
默认外调仍关闭，真实模型密钥、价格、供应商协议与地域授权没有改变。

本地启动脚本 `tools/run_dev_api.py` 使用专用工厂：仅当环境配置
`TUTOR_DURABLE_MODEL_INVOCATIONS_ENABLED=true` 时注入 SQL 回执；默认仍使用既有原型回执。
稳定密钥须通过 `TUTOR_PSEUDONYM_SECRET` 单独提供，不生成或打印密钥。
这个工厂不主动打开外调，也不替代已有供应商授权、报价或 OCR 模式配置。

exactly-once。持久换讲与 OCR 的生产存储、授权评测及 Q-04/Q-07 依赖仍保留，
